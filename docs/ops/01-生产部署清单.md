# 生产部署清单

> 将 CodeSchema 部署到生产环境的完整检查清单，确保服务稳定可靠。

---

## 1. 环境准备

- [ ] **Go 1.25+** 已安装（编译环境）
- [ ] **Docker 24+** 已安装（容器化部署）
- [ ] **磁盘空间** 充足（索引数据约仓库大小的 5-10%）
- [ ] **内存** ≥ 512MB（向量索引加载需要）
- [ ] **网络** 端口 8080/8081 未被占用

## 2. 配置文件

- [ ] 复制 `config.yaml.example` 为 `config.yaml`
- [ ] 修改 `project.name` 为实际项目名
- [ ] 修改 `project.root` 为仓库路径
- [ ] 修改 `server.auth_token` 设置认证 token（生产环境必填）
- [ ] 根据仓库规模调整 `scanner.workers`（通常 = CPU 核数）
- [ ] 根据内存调整 `storage.search.vector_dim`（低内存设 128-256）

## 3. 构建与部署

- [ ] `make build` 编译通过
- [ ] `docker build -t codeschema:latest .` 镜像构建通过
- [ ] `docker compose up -d` 服务启动成功
- [ ] `docker compose ps` 服务状态为 Up

## 4. 服务验证

- [ ] 健康检查：`curl http://localhost:8081/health` 返回 `{"status":"ok"}`
- [ ] 存储检查：`curl http://localhost:8081/health/db` 返回 `{"status":"ok"}`
- [ ] 向量检查：`curl http://localhost:8081/health/vector` 返回 `{"status":"ok"}`

## 5. 扫描验证

- [ ] 全量扫描：`codeschema scan /repo` 完成无错误
- [ ] 索引构建：扫描后自动构建索引（输出 `index built: N docs`）
- [ ] 搜索验证：`curl "http://localhost:8081/search?q=test&limit=5"` 返回结果

## 6. 监控配置

- [ ] 日志采集：配置日志收集（如 Loki、ELK）
- [ ] 指标采集：配置 Prometheus 抓取 `/metrics` 端点
- [ ] 告警规则：配置服务宕机告警
- [ ] 健康检查：使用 Docker HEALTHCHECK 或外部监控

## 7. 备份策略

- [ ] 数据目录 `./data` 定期备份（含 FTS/向量/IDF 索引）
- [ ] 备份频率：每日全量备份
- [ ] 保留周期：最近 7 天

## 8. 安全加固

- [ ] `auth_token` 已设置（非空）
- [ ] 防火墙限制 8080/8081 端口访问来源
- [ ] 使用 HTTPS 反向代理（如 Nginx）
- [ ] 容器以非 root 用户运行

## 9. 性能基线

- [ ] 记录首次扫描耗时
- [ ] 记录索引构建耗时
- [ ] 记录搜索 P95 延迟
- [ ] 记录内存占用基线

## 10. 应急方案

- [ ] 重启命令：`docker compose restart codeschema`
- [ ] 数据重置：删除 `./data` 目录后重新扫描
- [ ] 回滚方案：回退到上一版本镜像
- [ ] 降级方案：关闭语义搜索（`semantic: false`）降低内存占用
