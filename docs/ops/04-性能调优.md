# 性能调优

> CodeSchema 在不同规模的仓库和配置下有不同的性能表现，本文档提供调优指南。

---

## 1. 关键性能指标

| 指标 | 说明 | 关注点 |
|------|------|--------|
| **扫描耗时** | 全量扫描仓库的时间 | 大仓库 < 5min 可接受 |
| **索引构建耗时** | 构建 FTS + 向量索引的时间 | 通常 < 扫描耗时 |
| **搜索 P95 延迟** | 95% 搜索请求在多少 ms 内返回 | 目标 < 500ms |
| **内存占用** | 进程 RSS 内存 | 基准 ~100MB，索引加载后增加 |
| **磁盘占用** | 索引数据大小 | 约为仓库大小的 5-10% |

## 2. 调优参数

### 扫描并发数

| 参数 | 默认值 | 建议 |
|------|--------|------|
| `scanner.workers` | 4 | 小仓库(< 1k 文件) 4-8, 大仓库 8-16 |

```bash
# 增加并发 Worker 数
./codeschema scan --workers 16 ./large-repo
```

### 向量维度

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `storage.search.vector_dim` | 1024 | 维度越高语义越精确，但内存占用越大 |

```yaml
# 低内存环境降低向量维度
storage:
  search:
    vector_dim: 128  # 从 1024 降至 128，内存减少约 8 倍
```

### 文件监听

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `watcher.debounce_ms` | 300 | 防抖窗口，越小响应越快，但可能触发频繁 |
| `watcher.use_fsnotify` | false | 原生监听比轮询更高效 |

```bash
# 高频修改场景：使用原生监听 + 短防抖
./codeschema watch --fsnotify --debounce 200 ./repo
```

### 文件过滤

```yaml
# 排除无需扫描的大目录
watcher:
  ignore_dirs:
    - ".git"
    - "node_modules"
    - "target"
    - "build"
    - "vendor"
    - "dist"
    - ".next"
    - "__pycache__"

scanner:
  file_size_limit_mb: 10    # 超过 10MB 的文件跳过
  line_count_limit: 50000   # 超过 5 万行的文件跳过
```

## 3. 不同规模仓库的配置建议

### 小仓库（< 1,000 文件）

```yaml
scanner:
  workers: 4
storage:
  search:
    vector_dim: 1024
```

内存占用：~50-100MB | 扫描耗时：< 1s

### 中型仓库（1,000 - 50,000 文件）

```yaml
scanner:
  workers: 8
storage:
  search:
    vector_dim: 512   # 适当降低维度
```

内存占用：~100-300MB | 扫描耗时：1-30s

### 大型仓库（50,000 - 500,000 文件）

```yaml
scanner:
  workers: 16
  file_size_limit_mb: 5   # 严格限制文件大小
  line_count_limit: 10000 # 严格限制行数
storage:
  search:
    vector_dim: 256       # 降低维度节省内存
    semantic: false       # 可选：关闭语义搜索仅用 FTS
```

内存占用：~300-800MB | 扫描耗时：30s-5min

## 4. 内存优化策略

### 关闭语义搜索（最有效）

```yaml
storage:
  search:
    semantic: false   # 关闭向量索引，节省大量内存
    fts: true         # 仅保留 FTS 全文搜索
```

### 降低向量维度

```yaml
storage:
  search:
    vector_dim: 128   # 维度从 1024 降至 128
```

### 限制并发

```yaml
scanner:
  workers: 2          # 减少并发 Worker
```

## 6. 已知性能基准

| 仓库 | 文件数 | 扫描耗时 | 索引构建 | P95 搜索延迟 |
|------|--------|----------|----------|-------------|
| CodeSchema 自身 | 81 | 87ms | 12ms | 1.99ms |
| idcu-panel/backend | 312 | 190ms | 21ms | 2.99ms |

> 扩展性：4x 文件量 → 约 1.6x 扫描时间 / 1.9x P95 延迟，线性扩展性良好。
