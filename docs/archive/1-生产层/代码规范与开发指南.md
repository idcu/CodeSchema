# 代码规范与开发指南

> 写给谁：Golang 开发者、技术负责人、AI 编程工具（编码阶段的硬约束）
> 写什么：目录结构、命名规范、代码风格、分支策略、构建/测试/启动、commit 规范入口
> 核心原则：命名统一、目录职责单一、构建默认免 CGO、测试齐全、Commit 即档案
> 优先级：P0
> 最后更新：2026-08-17

---

## 1. 技术栈

- 语言：Go 1.25.2（模块 `github.com/idcu/codeschema`）
- 关键依赖：`modernc.org/sqlite`（纯 Go 免 CGO）、`chromem-go`（本地 replace `down/`）、`fsnotify`、`yaml.v3`、`onnxruntime_go`（`third_party/` patch，仅 `-tags onnx`）
- 可选驱动：`lib/pq`（-tags pg）、`go-redis/v9`（-tags redis）
- 不引入原生 cgo 强制依赖；默认构建 `go build ./...` 免 CGO/gcc。

## 2. 目录结构约定

| 目录 | 职责 | 约束 |
|---|---|---|
| `cmd/codeschema/` | 可执行入口（scan/watch/benchmark/agent-bench/mcp/serve/version/rebuild-kv） | 较薄；存储 dispatch 必须落在 cmd 层（防循环依赖） |
| `internal/<pkg>/` | 业务包 | 仅内部可见，不对外暴露 |
| `internal/parser/adapter/<name>/` | 各解析适配器 | 独立子包，可单独编译/测试 |
| `internal/store/` | 存储接口 + file/sqlite/pg/redis 驱动 | 经 cmd 层 build-tag 分发接线 |
| `docs/` | 文档体系 | 按圈层组织，改码必改档 |
| `scripts/` | 快捷脚本 | — |
| `third_party/` | onnxruntime_go patch | 上游升级需复核 |
| `down/` | chromem-go 本地源码 | replace 目标，随仓维护 |

> 包依赖方向：`cmd → internal/server → internal/service → {analyzer/ai/search/vector/store}`；`internal/parser` 以下依赖注入，适配器通过 `Register()` 注册，开闭原则。

## 3. 命名规范

- 包名：小写、单数、无下划线，与目录同名。
- 导出标识符：首字母大写；接口定义用行为名（如 `Store`、`VectorStore`、`Embedder`）。
- 常量/配置字段：使用 JSON/环境变量时遵循 `config` 包的 JSON tag 与 `CODESCHEMA_<SECTION>_<KEY>` 环境变量命名。
- 适配器：新增语言/解析源命名为 `<name>/` 子包 + `Register()`。
- 可选能力用「可选接口」表达：小接口（如 `store.SkippedWriter` / `store.CacheReader` / `store.DriverNamer`）供调用方类型断言探测，未实现时保留回退行为；不加进主接口避免强制所有实现改动。
- 吐槽点：避免 `Base`/`Util`/`Common`/`Manager` 堆叠；已有 `manager`/`helper` 实际用例如 `tenant.Manager`、`robust.recovery` 属既定命名，新增请先对照。

## 4. 代码风格

- 官方 `gofmt`；提交前 `go vet ./...` 通过。
- 注释语言：中文；公共导出符号必须有可读注释。
- 错误处理：使用 `internal/errors` 体系（`ErrXxx`），不吞错误；关键的"静默返回空结果"是反模式，必须显式报错或降级。
- 并发：优先 channel + goroutine；用 `-race` 验证。
- 规模/性能改动必须带验证数据（基准/内存/耗时打点），禁止"凭感觉快"。

## 5. 分支策略

- 主分支：`main`（仅接受评审后合并）。
- 特性开发：短生命周期分支 `feat/<scope>` 或按任务卡推进；本仓库实际以"plan任务/阶段"推进为主。
- 破坏性变更：不得直接上 `main`，须评审（见 AI协作规范 §6）。
- 不自行 push；除非明确指示否则仅 `git commit`。

## 6. 构建 / 测试 / 启动（速查）

```bash
make build          # 纯 Go 免 CGO
make test           # go test ./...
make test-race      # -race 竞态检测
make test-cover     # 覆盖率
make lint           # go vet
make cross          # 5 平台交叉编译
make bench          # Benchmark 回归（含 ScaleBench 的 BulkUpsert 看护）
make build-cgo      # CGO + 拷贝 ONNX 运行库（需 -tags onnx 才接 ONNX 嵌入器）
make models-serve   # 本地 HTTP 分发 ONNX 模型
```

常用命令：
```bash
go build ./... && go vet ./... && go test ./... -count=1
go build -tags onnx ./...        # 启用 ONNX 语义检索（需 gcc + onnxruntime 动态库）
go build -tags pg,redis ./...    # 启用 PG + Redis
./codeschema mcp --stdio --store ./data   # MCP stdio 直连
./codeschema serve --http :8081           # HTTP API（/viz 可视化）
```
