## 1. 错误类型体系

### 1.1 错误定义

```go
package errors

import "errors"

// 适配器错误
var (
    ErrNoAdapter          = errors.New("no adapter found for language")
    ErrParseFailed        = errors.New("parse failed")
    ErrSourceUnavailable  = errors.New("source unavailable")
    ErrParseTimeout       = errors.New("parse timeout")
)

// AI 增强错误
var (
    ErrBudgetExceeded     = errors.New("AI budget exceeded")
    ErrLLMUnavailable     = errors.New("LLM unavailable")
    ErrEnhanceFailed      = errors.New("enhance failed")
)

// 存储错误
var (
    ErrTxFailed           = errors.New("transaction failed")
    ErrKVWriteFailed      = errors.New("KV write failed")
    ErrVectorBuildFailed  = errors.New("vector index build failed")
)

// 通用错误
var (
    ErrFileNotFound       = errors.New("file not found")
    ErrInvalidConfig      = errors.New("invalid configuration")
)
```

### 1.2 错误处理策略

| 错误类型 | 处理方式 | 重试策略 |
|---|---|---|
| 适配器解析失败 | 记录日志，标记 `parse_status = 'parse_error'`，跳过该文件 | 不重试 |
| 适配器源不可用 | 降级到下一个可用适配器 | 最多降级 1 次 |
| AI 增强失败 | 记录日志，跳过增强 | 不重试 |
| 数据库连接失败 | 指数退避重试（3 次，1s/2s/4s） | 重试 3 次 |
| KV 写入失败 | 记录日志，后台异步补偿 | 异步重试 2 次 |

## 2. 日志规范

### 2.1 日志级别

| 级别 | 使用场景 |
|---|---|
| `ERROR` | 适配器解析失败、数据库连接丢失、AI 调用异常 |
| `WARN` | 适配器降级、KV 写入失败、预算超限、大文件跳过 |
| `INFO` | 扫描开始/结束、文件变更检测、索引状态变更 |
| `DEBUG` | 每文件解析耗时、每次 AI 调用详情、事务详情 |

### 2.2 日志格式

结构化 JSON 日志，包含以下字段：

```json
{
  "timestamp": "2026-08-13T10:00:00.000Z",
  "level": "INFO",
  "module": "scanner",
  "file": "src/main.go",
  "latency_ms": 15,
  "error": "",
  "message": "file parsed successfully"
}
```

**必选字段**：`timestamp`、`level`、`module`、`message`
**可选字段**：`file`、`latency_ms`、`error`、`language`、`adapter`

## 3. 监控指标

### 3.1 指标定义

| 指标 | 类型 | 标签 | 说明 |
|---|---|---|---|
| `http_requests_total` | Counter | `method`, `path`, `status` | HTTP 请求计数 |
| `http_active_requests` | Gauge | — | 进行中的 HTTP 请求数 |
| `scanner_processed_total` | Counter | `status` | 扫描器处理文件计数 |
| `scanner_files_total` | Gauge | — | 扫描发现文件数 |
| `scanner_errors_total` | Counter | `operation` | 扫描器错误计数 |
| `scanner_active_workers` | Gauge | — | 活跃 worker 数 |
| `analyzer_build_total` | Counter | `graph_type` | 代码图构建计数 |
| `analyzer_files_total` | Counter | `language` | 分析文件计数 |
| `analyzer_nodes_total` | Counter | `graph_type` | 图节点计数 |
| `analyzer_errors_total` | Counter | — | 分析器错误计数 |
| `parser_fallback_total` | Counter | `language` | 适配器降级回退计数 |
| `lsp_missing_compile_commands_total` | Counter | — | clangd 初始化未发现 `compile_commands.json`（C/C++ 可能静默空符号） |
| `lsp_parse_empty_symbols_total` | Counter | `lang` | 解析非空 C/C++ 文件却返回 0 符号（疑似缺项目上下文） |
| `lsp_parse_errors_total` | Counter | `reason` | LSP 解析请求失败次数 |
| `lsp_retries_total` | Counter | `method` | LSP 请求重试次数（瞬时失败） |
| `lsp_malformed_frames_total` | Counter | `kind` | 被静默恢复的异常 LSP 协议帧（已暴露为 WARN：content_length / json / orphan） |

### 3.2 指标收集方式

- 使用**纯 Go 自研 metrics 实现**（`internal/metrics`，无外部依赖）暴露指标，格式兼容 Prometheus text exposition。
- HTTP 端点 `GET /metrics` 提供 Prometheus 格式的指标数据。
- 仅支持 Counter 和 Gauge 两种类型（无 Histogram/Summary）。

## 4. 健康检查

### 4.1 端点定义

| 端点 | 检查内容 | 预期响应 |
|---|---|---|
| `GET /health` | 整体健康状态 | `{"status": "ok"}` |
| `GET /health/db` | 数据库连接 | `{"status": "ok", "latency_ms": 5}` |
| `GET /health/kv` | KV 缓存连接 | `{"status": "ok"}` |
| `GET /health/vector` | 向量库状态 | `{"status": "ok", "type": "memory", "note": "In-memory vector index active..."}` |

### 4.2 健康检查实现

```go
// internal/server/health.go
package server

type HealthHandler struct {
    db     *sql.DB
    kv     *redis.Client
    vector *vector.Indexer
}

func (h *HealthHandler) Check(ctx context.Context) HealthResponse {
    dbStatus := h.checkDB(ctx)
    kvStatus := h.checkKV(ctx)
    vecStatus := h.checkVector(ctx)
    overall := "ok"
    if dbStatus != "ok" || kvStatus != "ok" || vecStatus != "ok" {
        overall = "degraded"
    }
    return HealthResponse{
        Status: overall,
        DB:     dbStatus,
        KV:     kvStatus,
        Vector: vecStatus,
    }
}
```

## 5. 安全设计

### 5.1 API 安全

| 风险 | 缓解措施 |
|---|---|
| 未授权访问 | MCP Server 支持可选的 bearer token 认证；HTTP API 支持 API Key |
| 路径遍历 | 所有文件路径参数做规范化检查，拒绝包含 `..` 的路径 |
| 大文件 DoS | `byte_size` 阈值旁路，超限文件标记为 `parse_skipped` |
| 并发耗尽 | worker pool 限制并发数，请求队列长度上限 |

### 5.2 数据安全

| 风险 | 缓解措施 |
|---|---|
| SQLite 文件泄露 | 默认文件权限 0600，支持加密存储（P2） |
| 向量库数据泄露 | 向量数据不包含原始代码，仅含 embedding 向量元信息 |
| 敏感信息索引 | 不索引密码、密钥等敏感文件（通过 `.gitignore` 模式过滤） |

### 5.3 进程安全

| 风险 | 缓解措施 |
|---|---|
| LSP 子进程逃逸 | 子进程以最小权限运行，限制可执行路径白名单 |
| 第三方工具供应链 | 所有外部工具通过版本锁定和 checksum 校验引入 |
| 配置文件注入 | 配置文件使用严格的 schema 校验，拒绝未知字段 |

### 5.4 安全中间件实现

```go
// internal/server/middleware.go
package server

// AuthMiddleware 验证请求认证信息。
func AuthMiddleware(authToken string) func(http.Handler) http.Handler {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            if authToken != "" {
                token := r.Header.Get("Authorization")
                if token != "Bearer "+authToken {
                    http.Error(w, "unauthorized", http.StatusUnauthorized)
                    return
                }
            }
            next.ServeHTTP(w, r)
        })
    }
}

// PathTraversalMiddleware 防止路径遍历攻击。
func PathTraversalMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        path := r.URL.Query().Get("path")
        if path != "" && strings.Contains(path, "..") {
            http.Error(w, "invalid path", http.StatusBadRequest)
            return
        }
        next.ServeHTTP(w, r)
    })
}
```

## 6. 开发指南

### 6.1 实现步骤

1. **实现错误类型定义**：在 `internal/errors` 包中定义所有错误变量，实现错误处理策略函数。
2. **实现结构化日志**：集成日志库（如 `slog`/`zap`），配置 JSON 格式输出，实现日志级别控制。
3. **实现监控指标收集**：在 `internal/metrics` 包中定义指标注册和收集逻辑，在关键路径打点。
4. **实现健康检查端点**：在 `internal/server/health.go` 中实现各端点检查逻辑，注册到 HTTP 路由。
5. **实现安全中间件**：在 `internal/server/middleware.go` 中实现认证、路径检查、限流等中间件。
6. **单元测试**：覆盖错误处理路径、健康检查逻辑、安全中间件边界情况。
