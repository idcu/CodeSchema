## 1. 阶段概述

### 1.1 目标

为 CodeSchema 系统构建完整的语义检索与全文搜索能力，包括：

- **P8.1**：定义 FTSEngine / VectorStore / Embedder 等核心接口，实现内存 mock 骨架，集成 Service 层与接口层
- **P8.2**：实现磁盘持久化存储（PersistentStore / PersistentFTS），纯 Go 本地 Embedder（LocalEmbedder），更新配置模型
- **P8.3**：实现 IndexBuilder 自动索引构建器，Scanner 增量索引回调，CLI 四个命令集成，10 个测试覆盖
- **P8.3 优化**：IDF 词典持久化（SaveIDF / LoadIDF）、异步索引队列（StartAsync / StopAsync / EnqueueIndex）、文件删除索引同步清理（BuildAndRemove / SetOnDelete）

### 1.2 范围

涉及 4 个核心包（`vector` / `search` / `service` / `config`）、1 个 CLI 入口（`cmd/codeschema/main.go`）、1 个扫描器扩展（`internal/scanner/scanner.go`），共 **12 个新增/修改文件**，**73 个新增测试**。

## 6. 遗留 TODO 及风险

### 6.1 已知风险

| 风险 | 影响 | 缓解措施 | 计划解决 |
|------|------|----------|----------|
| **LocalEmbedder 精度有限** | 基于 TF-IDF 哈希，精度低于真实语义模型（bge-small-zh） | 已提供 ONNX 双路径（bge-small-zh-v1.5，多语料 recall 全胜，R@1=1.00）+ 自动降级；**语义质量定案（T2-3）**：ONNX 真实复测 Recall@1/@3/@5=1.00 vs Local 0.42/0.58/0.83，默认 Local 兜底 / 语义敏感场景 `-tags onnx` | ✅ 已解决 |
| ~~**异步索引队列单 worker**~~ | 单 goroutine 消费可能成为瓶颈 | 已扩展可配置多 worker（`StartAsync(queueSize, numWorkers)`，watch 用 2 worker） | ✅ |
| **删除索引时未反向删除 store 文件记录** | 索引清理仅为文档级，store 层文件记录由 PollWatcher 自动处理 | 当前行为可接受，不影响功能 | 低优先级 |
| ~~**异步索引错误未集成全局日志系统**~~ | 错误仅通过 onError 回调通知 | 已接入 `internal/log`（asyncWorker 使用 log.WithModule） | ✅ |
| ~~**chromem-go 集成未完成**~~ | 需网络下载外部依赖 | 已集成 `internal/vector/chromem.go`（可选实现，12 测试），生产默认 PersistentStore | ✅ |
| ~~SQLite FTS5 未集成~~（已落地） | 原计划需网络下载 `mattn/go-sqlite3` | 已用纯 Go PersistentFTS 落地，无需 FTS5 | ✅ |
| ~~**向量索引原文未持久化**~~（已落地） | /viz 文档详情 Content 为空 | `vector.DocContentStore` 持久化原文（Persistent/Memory 实现，旧文件兼容），IndexBuilder 写入，/viz 展示类/方法原文（T2-2） | ✅ |
| ~~**模型公网分发未闭环**~~（已落地） | 注册表 URL 占位，仅本地分发 | 注册表 URL 回填 + `make models-serve` 本地 HTTP 分发 + 真实制品 HTTP 端到端 PASS（T2-1） | ✅ |
