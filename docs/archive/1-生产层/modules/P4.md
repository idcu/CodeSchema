# P4 分析层（Analysis Layer）

> 模块编号：P4 ｜ 父模块：无（一级） ｜ 完成度：96%（Analyzer 100%，AI 87%）

## 🎯 模块用途

分析层赋予系统「**理解代码**」的能力：

1. **P4_1 代码图与影响面**：基于已入库的调用/继承关系构建 4 张图（调用图、类层次、反向引用、文件图），支撑「改一处反查影响面」与「定位关联单测」。
2. **P4_2 AI 增强**：用 LLM 做六类标签推导（layer/biz/tech/risk/test/lang）、注释补全、同名方法消歧——把确定性规则推导之外的语义理解交给 AI。

## 🧱 拆分逻辑说明

按**业务域（确定性推理 vs 非确定性 AI）**划分——这是刻意为之：

- Analyzer 是纯图结构推理（确定性、可测试、无外部依赖），是影响面分析的基础设施。
- AI 是非确定性推理（依赖外部 LLM 服务、有 token 预算、可能失败），必须可优雅降级。
- 两者生命周期与风险不同：AI 挂了不影响 Analyzer；预算耗尽回退规则标签。

边界：Analyzer 读 Store 里的 IR 记录建图；AI 可注入 Analyzer（标签补全）也可注入 Service（查询期消歧），均通过 `SetEnhancer`/`WithAIEnhancer` 注入。

## ⚙️ 技术说明

**技术选型**：纯 Go 图算法（BFS/DFS、最短路径）；AI 侧为 OpenAI 兼容 HTTP 客户端 + token 预算控制。

**对外接口契约**：
- Analyzer：`BuildAll`/`BuildCallGraph`/`BuildClassHierarchy`/`BuildReverseIndex`/`BuildFileGraph`/`FindImpactNodes`/`ShortestPath`/`TagAll`/`Analyze`（见 P4_1）
- AI：`EnhanceTag`/`EnhanceDoc`/`Disambiguate`（见 P4_2）

**依赖的下层模块**：P3_1（IR 模型）、P7 存储层（读图数据）、P4_2（Analyzer 可注入 Enhancer）、P8 公共模块。

**数据模型**：`CallGraph`/`ClassHierarchy`/`ReverseIndex`/`FileGraph` 四种图结构（内存态）。

## 🔄 替代方案

- 图存储用 neo4j 等外部图数据库：持久化更强，但对当前单机 KV 场景过重，内存图 + Store 重建足够。
- 标签纯靠 AI：无 LLM 时系统退化，规则推导兜底是必须的（当前设计正确）。

- 影响面分析在大仓库下的内存占用（图全量驻内存）需 benchmark 看护。
