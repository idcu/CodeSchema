# P8_1 配置系统 【公共模块】

> 模块编号：P8_1 ｜ 父模块：P8 横切公共模块 ｜ 完成度：100% ｜ 代码：`internal/config`（config.go 836 行 / parse.go 267 行）

## 🎯 模块用途

统一管理全系统配置：YAML/JSON 配置加载、环境变量覆盖（优先级高于文件、低于 CLI 参数）、**运行时热重载**（`ConfigWatcher`，watch/mcp/serve 长驻命令支持，2s 轮询）。解决「配置来源多、运行期想改配置要重启」的问题。

## 🧱 拆分逻辑说明

按**职责边界（横切能力）**独立：配置是全二进制启动链的入口依赖，任何命令都要先 `config.Load`。独立成模块后，配置源（文件/环境变量/热更新）的扩展不影响任何业务包。

## ⚙️ 技术说明

**技术选型**：`gopkg.in/yaml.v3`；Go 标准库 `encoding/json`、`os`（环境变量）。

**对外接口契约**：
- `Load(path) (*Config, error)` — 加载 YAML/JSON
- `LoadFromEnv(cfg)` — 环境变量覆盖（`CODESCHEMA_*` 前缀约定）
- `NewConfigWatcher(path, cfg, callback)` + `Start/Stop/GetConfig` — 热重载

**依赖的下层模块**：无。

**数据模型**：`Config`（storage/scanner/watcher/server/ai/search/vector 分区配置）。

## 🔄 替代方案

- Viper：功能全但重（支持多种格式 + 远程配置），当前 YAML/JSON + env 足够。
- 静态配置不热更新：运维体验差，热重载是 P9 明确诉求。
