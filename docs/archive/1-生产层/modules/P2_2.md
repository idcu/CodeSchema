# P2_2 增量扫描器 Scanner

> 模块编号：P2_2 ｜ 父模块：P2 编排层 ｜ 完成度：100% ｜ 代码：`internal/scanner`

## 🎯 模块用途

负责仓库的**全量扫描与增量更新**：遍历仓库文件，按扩展名识别语言，通过解析适配器注册中心（P3_1）将代码转为 IR，经 `UpsertIR`/`BulkUpsert` 入库，并计算 SHA-256 内容哈希判断是否变更。是「代码 → 元数据」写路径的执行引擎。

## 🧱 拆分逻辑说明

按**职责边界（写路径执行者）**独立：Scanner 只关心「文件集合 → Store 中的 IR」，不关心变更从哪来（Watcher 负责）、不关心何时触发（Scheduler 负责）。因此 `scan` 命令可独立调用它，`watch` 命令通过回调（`SetOnIndex`/`SetOnDelete`）复用同一套增量逻辑——这是把它从 Watcher/Scheduler 拆出的直接收益。

## ⚙️ 技术说明

**技术选型**：Go 标准库 + `crypto/sha256`（内容哈希）；并发 worker 池解析（`--workers`）；`sync` 并发控制。

**对外接口契约**：
- `NewScanner(st store.Store, reg *parser.Registry, workers int)` 
- `ScanAll(ctx, repoPath)` — 全量扫描入库
- `ProcessFile(ctx, path)` — 单文件增量处理
- `SetOnIndex(ctx, filePath)` / `SetOnDelete(ctx, filePath)` — 索引增量回调（由 watch 命令注入）
- 内部：`detectLang`（扩展名→语言，与 `adapter.ExtToLang` 同步）、`hash.go`（内容哈希）

**依赖的下层模块**：P3_1 解析核心（Registry + IR）、P7 存储层（Store.UpsertIR/BulkUpsert）、P8_2 日志、P8_3 指标、P8_4 追踪。

**数据模型**：消费 `parser.IRDocument`；产出 `store.FileRecord`（含 content hash / parse status）。

## 🔄 替代方案

- 用 `go-git` 差异检测替代内容哈希：可只处理 diff 文件，但引入大依赖且对非 git 仓库不适用，当前 SHA-256 + 状态比较足够。
