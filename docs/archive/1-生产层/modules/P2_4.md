# P2_4 调度器 Scheduler

> 模块编号：P2_4 ｜ 父模块：P2 编排层 ｜ 完成度：100% ｜ 代码：`internal/scheduler`

## 🎯 模块用途

对高频文件变更事件做**防抖合并与批量调度**。文件编辑时事件可能以毫秒级频率爆发，直接逐条解析入库会造成 IO 与 CPU 浪费；Scheduler 在时间窗口内合并同一路径的事件、控制并发，避免风暴。

## 🧱 拆分逻辑说明

按**职责边界（时间窗口调度）**独立：防抖/批量的时序逻辑与「事件来源」（Watcher）和「事件处理」（Scanner）解耦。独立后既可被 Watcher 使用，也能被其他场景（如 CI 批处理）复用，且时序策略（窗口大小、批量上限）可独立演进。

## ⚙️ 技术说明

**技术选型**：Go 标准库 `time` + goroutine；依赖 `internal/robust`（优雅关闭/恢复）。

**对外接口契约**：
- `NewScheduler(debounceMs, maxBatch int)` — 创建调度器
- `Start(ctx, handler)` — 启动调度循环，`handler(ctx, path)` 为防抖后的处理回调（由 Scanner 提供）
- 队列内部维护待处理路径集合，窗口内合并

**依赖的下层模块**：P8_6 健壮性组件。

**数据模型**：内部待处理路径队列（去重集合）。

## 🔄 替代方案

- 直接用 `fsnotify` 的 debounce 第三方库：策略不可控，当前手写窗口合并足够且可测。
- 事件直接透传不防抖：小仓库可行，大仓库解析风暴不可接受。
