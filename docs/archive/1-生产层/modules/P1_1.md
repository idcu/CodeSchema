# P1_1 CLI 命令行入口

> 模块编号：P1_1 ｜ 父模块：P1 接入层 ｜ 完成度：100% ｜ 代码：`cmd/codeschema`

## 🎯 模块用途

提供人工操作 CodeSchema 的全部命令入口：扫描仓库入库、文件监听增量更新、重建 KV 缓存、运行基准、启动 MCP/HTTP 服务、查看版本。同时承担 **存储驱动分发**（`store_dispatch.go`：sqlite/pg/redis 经 build-tag 接线，避免 `internal/store` 循环依赖）与**解析适配器注册**（统一走 `internal/runtime.NewParserRegistry`，tree-sitter 兜底 + 可选 LSP/SCIP/CodeGraph 高精度优先，`scan`/`watch` 复用同一装配）。

## 🧱 拆分逻辑说明

按**部署单元**独立成模块：CLI 是唯一被直接执行的二进制入口，是上层协议（MCP/HTTP）与批处理（scan/watch/benchmark）的公共装配点，所有模块在此完成依赖注入（如 `WithImpactAnalyzer`/`WithAIEnhancer`/`WithSearcher`）。

与兄弟模块（P1_2 MCP、P1_3 HTTP）的边界：CLI 负责「启动什么进程、注入哪些组件」，Server 负责「进程启动后怎么服务」。

## ⚙️ 技术说明

**技术选型**：Go 标准库 `flag`（每个子命令独立 `flag.NewFlagSet`）；配置系统 `internal/config`；优雅关闭 `robust.NewGracefulManager(30s)`。

**命令清单**：

| 命令 | 说明 | 关键标志 |
|---|---|---|
| `scan <path>` | 全量扫描入库 + 建索引 + 标签推导 | `--workers --store` |
| `watch <path>` | 增量监听（默认轮询，`--fsnotify` 切原生） | `--debounce --fsnotify` |
| `rebuild-kv` | 重建 KV 缓存 | — |
| `benchmark` | 全链路基准（多仓库对比） | — |
| `mcp` | 启动 MCP Server | `--addr --auth-token --stdio --print-config` |
| `serve` | 启动 HTTP + `/viz` | `--http --auth-token` |
| `version` | 版本信息 | — |

**对外接口契约**：命令行语法即契约（`--config` 全局配置 + 子命令标志）；`mcp --print-config` 输出各客户端（VS Code/JetBrains/Claude Code/Cursor）接入配置片段。

**依赖的下层模块**：P2_1 Service、P2_2 Scanner、P2_3 Watcher、P2_4 Scheduler、P6_2 嵌入器 + P6_3 模型分发（向量栈装配）、P7 存储层全驱动、P8 全部公共模块。

**数据模型**：无，仅装配现场（对象注入与生命周期管理）。

## 🔄 替代方案

- 多命令分发改 `cobra`：命令帮助/补全更友好，但 7 个子命令手写 `flag` 已够用，引入 cobra 徒增体积。
