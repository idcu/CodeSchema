## 2. 历史坑点与既定结论（勿轻易推翻）

- **ONNX Runtime 版本锁定**：必须用 v1.28.0 匹配 `onnxruntime_go`（API 28）；v1.21.0 与 v1.23.2 已验证不兼容底座（另：docs/ops 曾记 1.23.2，实测以 1.28.0 为准）。`make build-cgo` 自动拷贝动态库；`-tags onnx` 才接 ONNX 嵌入器。
- **k5 认知**：`koa`（前端上下文）与 Go 存储分层解耦；中间件勿从 Express 中间件 wrap（用原生 Koa 风格），避免 ctx 泄漏。
- **SQLite 写性能**：逐文件多事务在 10 万文件上极慢（77-237s）；生产必须走 `BulkUpsert`（单事务+预编译，100k ~5-14s）。
- **Go import 解析**：`CompositeResolver` 优先级链（Go→Java→Gradle→启发式）；Go 模块路径精确匹配优先。
- **chromem-go**：本地 replace `down/`，作为向量后端参考实现；生产路径当前固定 PersistentStore+MemoryStore（config `vector.driver` 仅占位）。
- **超大进程替换** 已由 play 层（可用宽的 binary 替换）承接；见 `DEV_PROGRESS.md`。
- **向量召回**：LocalEmbedder(TF-IDF) R@1≈0.42 → ONNX(bge-small-zh-v1.5) R@1=1.00；语义敏感必须 `-tags onnx`。

|---|---|---|---|
| onnxruntime_go | go.mod + `third_party/onnxruntime_go_patch` | 上游升级需复核 API 版本 | 保持 1.28.0 |
