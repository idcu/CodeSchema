## 1. 威胁面概述

CodeSchema 对外暴露两类监听：HTTP API（默认 `:8081`）与 MCP Server（默认 `:8080`），均可选 Bearer 认证；解析可能启动 LSP 子进程（gopls/jdtls/clangd）。因此威胁面包括：未授权访问、路径遍历、索引/向量数据泄露、进程逃逸与供应链。

## 2. API 安全

| 风险 | 缓解措施 |
|---|---|
| 未授权访问 | MCP Server 支持可选 bearer token；HTTP 支持 API Key（`server.auth_token`） |
| 路径遍历 | 所有文件路径参数做规范化检查，拒绝含 `..` 的路径 |
| 大文件 DoS | `byte_size` 阈值旁路，超限标记 `parse_skipped` |
| 并发耗尽 | worker pool 限制并发，请求队列长度上限 |

## 3. 数据安全

| 风险 | 缓解措施 |
|---|---|
| SQLite 文件泄露 | 默认文件权限 0600；加密存储 P2 |
| 向量库数据泄露 | 向量数据不包含原始代码，仅含 embedding 向量元信息 |
| 敏感信息索引 | 不索引密码/密钥等敏感文件（`.gitignore` 模式过滤） |

## 4. 进程安全

| 风险 | 缓解措施 |
|---|---|
| LSP 子进程逃逸 | 子进程以最小权限运行，限制可执行路径白名单 |
| 第三方工具供应链 | 外部工具版本锁定 + checksum 校验（如 ONNX 模型 SHA-256） |
| 配置文件注入 | 配置严格 schema 校验，拒绝未知字段 |

## 5. 安全中间件实现

```go
// internal/server/middleware.go
// AuthMiddleware：验证 Bearer token；authToken 为空则跳过
func AuthMiddleware(authToken string) func(http.Handler) http.Handler
// PathTraversalMiddleware：拒绝 query 参数含 ".." 的路径
func PathTraversalMiddleware(next http.Handler) http.Handler
```
要求：中间件单测覆盖认证成功/失败、合法路径/路径遍历边界。

## 6. 错误类型与降级（点到即止）

错误使用 `internal/errors` 体系，映射可观测与降级策略（详见 [技术设计文档 §7](../1-生产层/技术设计文档.md)）：
- 适配器解析失败 → 标记 `parse_error` 跳过；适配器源不可用 → 最多降级 1 次。
- AI 增强失败 → 跳过（受 `ErrBudgetExceeded`/`ErrLLMUnavailable` 约束）。
- DB 连接失败 → 指数退避重试（1s/2s/4s）；KV 写失败 → 日志 + 异步补偿。
- **静默空结果反模式**被禁止。

## 7. 合规自查清单

- [ ] 生产认证已开启（`auth_token` 非空）
- [ ] 对外监听已收敛（必要时仅内网开放）
- [ ] 索引目录权限 0600，密钥/密码不外泄
- [ ] 外部二进制（ONNX 运行库、LSP）版本与 checksum 锁定
- [ ] 路径遍历与限流中间件已生效
- [ ] 日志不含明文密钥（`api_key` 非明文落盘）
