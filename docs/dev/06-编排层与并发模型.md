## 1. 概述

编排层负责协调扫描、调度、文件监听与事务管理，是系统的并发控制中枢。核心模块：

- **Scanner**：全量扫描 worker pool，按文件分配独立事务。
- **Scheduler**：任务调度与防抖排队，管理增量事件流。
- **Watcher**：fsnotify 文件监听，事件防抖合并与降级。

---

## 2. 并发扫描模型

### 2.1 全量扫描 worker pool

```go
// Scanner 的并发模型设计：
//
// 1. 全量扫描：
//    - 使用 worker pool（默认 4 个 worker，可配置）
//    - 每个 worker 处理一个文件，调用 ProcessFile
//    - 每个 ProcessFile 使用独立事务
//    - 使用 semaphore 控制并发文件数，避免同时打开过多文件句柄
//
// 2. 增量监听：
//    - 单 goroutine 顺序处理 fsnotify 事件
//    - 防抖窗口内合并重复事件
//    - 每个事件触发 ProcessFile（独立事务）
//
// 3. 构建反向引用索引：
//    - 全量扫描时：单线程构建，避免并发写冲突
//    - 增量更新时：使用 sync.RWMutex 保护 reverse_import_cache
```

### 2.2 并发安全措施

- `file` 表的 `UNIQUE(absolute_path)` 约束防止重复插入。
- 每个 `ProcessFile` 独立事务，避免大事务持锁。
- 构建反向引用索引时使用读写锁保护共享缓存。

## 3. 事务边界与隔离级别

| 操作 | 事务边界 | 隔离级别 | 说明 |
|---|---|---|---|
| 单文件解析入库 | 1 个文件 = 1 个事务 | `IMMEDIATE`（SQLite） | 避免 `INSERT OR UPDATE` 竞争 |
| 全量扫描 | 每文件独立事务 | `IMMEDIATE` | 大文件不阻塞其他文件 |
| 重建 KV | 1 个事务 | `DEFERRED` | 只读操作，允许并发 |
| 反向引用重建 | 1 个事务 | `EXCLUSIVE` | 写操作，不允许并发 |

**P2 PostgreSQL 迁移时**：

- 使用 `READ COMMITTED` 隔离级别（默认）。
- 大文件分批写入，使用 `SAVEPOINT` 支持部分回滚。
- 使用 `LISTEN/NOTIFY` 实现跨进程索引变更通知。

## 4. 防抖与排队策略

### 4.1 防抖策略

- fsnotify 事件在 300ms 窗口内防抖合并。
- 同一文件的多次变更事件，只触发一次 `ProcessFile`。

### 4.2 排队策略

- 防抖窗口结束后，变更文件按顺序入队，由 watcher goroutine 逐个处理。
- 如果队列长度超过阈值（默认 1000），触发"全量重新扫描"降级。

### 4.3 配置参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `scanner.workers` | `4` | 并发解析 worker 数 |
| `scanner.file_size_limit_mb` | `10` | 超过此大小的文件标记为 `parse_skipped` |
| `scanner.line_count_limit` | `50000` | 超过此行数的文件标记为 `parse_skipped` |
| `watcher.debounce_ms` | `300` | 防抖窗口（毫秒） |
| `watcher.queue_threshold` | `1000` | 队列阈值，超限触发全量扫描降级 |

## 5. Scanner 模块设计

```go
package scanner

type Scanner struct {
    store    *store.Store
    registry *parser.Registry
    workers  int
    semaphore chan struct{}
}

func NewScanner(store *store.Store, registry *parser.Registry, workers int) *Scanner {
    return &Scanner{
        store:     store,
        registry:  registry,
        workers:   workers,
        semaphore: make(chan struct{}, workers),
    }
}

// ScanAll 全量扫描仓库目录
func (s *Scanner) ScanAll(ctx context.Context, root string) error {
    files := listFiles(root)
    errCh := make(chan error, len(files))
    var wg sync.WaitGroup

    for _, file := range files {
        select {
        case <-ctx.Done():
            return ctx.Err()
        case s.semaphore <- struct{}{}:
        }
        wg.Add(1)
        go func(path string) {
            defer wg.Done()
            defer func() { <-s.semaphore }()
            errCh <- s.ProcessFile(ctx, path)
        }(file)
    }
    wg.Wait()
    close(errCh)
    return collectErrors(errCh)
}
```

## 8. Analyzer 代码图分析器

### 8.1 概述

Analyzer 模块负责从 Store 中读取已解析的 IR 数据，构建跨文件的代码关系图。位于解析流水线的下游：Scanner 解析文件 → Store 存储 IR → Analyzer 构建图。

### 8.2 四种图结构

| 图类型 | 数据结构 | 用途 |
|---|---|---|
| 调用图（CallGraph） | MethodFQN → Callers/Callees | 方法间调用关系分析、影响面分析 |
| 类层次（ClassHierarchy） | ClassFQN → Parents/Children | 继承/实现关系树 |
| 反向引用索引（ReverseIndex） | filePath → References/Imports | 文件被哪些文件引用 |
| 文件依赖图（FileGraph） | filePath → Imports/ImportedBy | 文件间 import/include 依赖 |

### 8.3 核心接口

```go
package analyzer

type Analyzer struct {
    store store.Store
}

func NewAnalyzer(st store.Store) *Analyzer

// 构建单个图
func (a *Analyzer) BuildCallGraph(ctx context.Context) (*CallGraph, error)
func (a *Analyzer) BuildClassHierarchy(ctx context.Context) (*ClassHierarchy, error)
func (a *Analyzer) BuildReverseIndex(ctx context.Context) (*ReverseIndex, error)
func (a *Analyzer) BuildFileGraph(ctx context.Context) (*FileGraph, error)

// 一次遍历构建所有图
func (a *Analyzer) BuildAll(ctx context.Context) (*CallGraph, *ClassHierarchy, *ReverseIndex, *FileGraph, error)

// 分析查询
func (a *Analyzer) FindImpactNodes(ctx context.Context, methodFQN string, depth int) (callers, callees []string, err error)
func (a *Analyzer) ShortestPath(ctx context.Context, from, to string) ([]string, error)
func (a *Analyzer) Analyze(ctx context.Context) (*ModuleSummary, error)
```

### 8.4 模块概要

`Analyze` 方法返回 `ModuleSummary`，包含：
- 文件/类/方法/调用总数统计
- 按语言分布统计
- 孤方法（无调用者的方法）
- 热点方法（被调用最多的 Top 20）

### 8.5 实现步骤

1. **定义图数据结构**（`internal/analyzer/graph.go`）：
   - CallGraph：AddNode/AddEdge/GetCallers/GetCallees/NodeCount/EdgeCount
   - ClassHierarchy：AddNode/AddParent/NodeCount
   - ReverseIndex：AddReference/AddImport/GetReferencedBy/GetImports
   - FileGraph：AddNode/AddEdge/NodeCount

2. **实现分析器**（`internal/analyzer/analyzer.go`）：
   - 从 Store 批量读取文件/类/方法/调用记录
   - **单次遍历**完成所有图的构建（BuildAll），预构建 import 索引后合并入主循环
   - BFS 最短路径查找
   - 热点方法排序
   - **P1: 反向引用索引** — 通过 `buildImportIndex` 构建 import 路径到文件路径的查找映射，支持多策略匹配（直接匹配、最后一段匹配、点号替换匹配）
   - **P1: 父子关系** — `buildClassHierarchyNode` 通过 `ClassRecord.ParentFQNs` 建立类继承/实现关系
   - **P2: Go 模块路径解析** — `resolveImport` 方法优先采用 Go 模块路径精确解析（如 `codeschema/internal/store` → `internal/store`），失败时回退到启发式匹配；通过 `Analyzer.SetModulePath` 设置模块路径
   - **P3: 多语言 ImportResolver 体系** — 定义 `ImportResolver` 接口，实现 `GoResolver`/`JavaResolver`/`CompositeResolver`/`heuristicResolver` 四种解析器：
     - `GoResolver`：模块路径精确解析（`codeschema/internal/store` → `internal/store`）
     - `JavaResolver`：支持 FQCN 导入（`com.example.service.UserService`）、通配符导入（`com.example.*`）、Java 标准库过滤（`java.*`/`javax.*`/`org.springframework.*` 等 23 个前缀）、Maven/Gradle 源根目录剥离（默认 `src/main/java`、`src/main/kotlin`、`src/test/java`、`src/test/kotlin`）
     - `CompositeResolver`：按优先级依次尝试每个注册的解析器，首个返回非空结果即停止
     - `heuristicResolver`：最终回退，支持直接匹配、最后一段匹配、`.` 替换为 `/` 后匹配
     - 通过 `Analyzer.SetJavaSourceRoots` 动态设置 Java 源根目录

3. **扩展 Store 接口**（`internal/store/store.go`）：
   - GetAllFiles：返回所有文件记录
   - GetClassesByFileID：按文件查询类记录
   - GetMethodsByClassID：按类查询方法记录
   - GetCallsByFileID：按文件查询调用记录
   - **P1: `FileRecord.Imports`** 持久化文件级 import 元数据
   - **P1: `ClassRecord.ParentFQNs`** 持久化类继承关系
