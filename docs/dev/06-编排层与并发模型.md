## 1. 概述

编排层负责协调扫描、调度、文件监听与事务管理，是系统的并发控制中枢。核心模块：

- **Scanner**：全量扫描 worker pool，按文件分配独立事务。
- **Scheduler**：任务调度与防抖排队，管理增量事件流。
- **Watcher**：fsnotify 文件监听，事件防抖合并与降级。

---

## 2. 并发扫描模型

### 2.1 全量扫描 worker pool

```go
// Scanner 的并发模型设计：
//
// 1. 全量扫描：
//    - 使用 worker pool（默认 4 个 worker，可配置）
//    - 每个 worker 处理一个文件，调用 ProcessFile
//    - 每个 ProcessFile 使用独立事务
//    - 使用 semaphore 控制并发文件数，避免同时打开过多文件句柄
//
// 2. 增量监听：
//    - 单 goroutine 顺序处理 fsnotify 事件
//    - 防抖窗口内合并重复事件
//    - 每个事件触发 ProcessFile（独立事务）
//
// 3. 构建反向引用索引：
//    - 全量扫描时：单线程构建，避免并发写冲突
//    - 增量更新时：使用 sync.RWMutex 保护 reverse_import_cache
```

### 2.2 并发安全措施

- `file` 表的 `UNIQUE(absolute_path)` 约束防止重复插入。
- 每个 `ProcessFile` 独立事务，避免大事务持锁。
- 构建反向引用索引时使用读写锁保护共享缓存。

## 3. 事务边界与隔离级别

| 操作 | 事务边界 | 隔离级别 | 说明 |
|---|---|---|---|
| 单文件解析入库 | 1 个文件 = 1 个事务 | `IMMEDIATE`（SQLite） | 避免 `INSERT OR UPDATE` 竞争 |
| 全量扫描 | 每文件独立事务 | `IMMEDIATE` | 大文件不阻塞其他文件 |
| 重建 KV | 1 个事务 | `DEFERRED` | 只读操作，允许并发 |
| 反向引用重建 | 1 个事务 | `EXCLUSIVE` | 写操作，不允许并发 |

**P2 PostgreSQL 迁移时**：

- 使用 `READ COMMITTED` 隔离级别（默认）。
- 大文件分批写入，使用 `SAVEPOINT` 支持部分回滚。
- 使用 `LISTEN/NOTIFY` 实现跨进程索引变更通知。

## 4. 防抖与排队策略

### 4.1 防抖策略

- fsnotify 事件在 300ms 窗口内防抖合并。
- 同一文件的多次变更事件，只触发一次 `ProcessFile`。

### 4.2 排队策略

- 防抖窗口结束后，变更文件按顺序入队，由 watcher goroutine 逐个处理。
- 如果队列长度超过阈值（默认 1000），触发"全量重新扫描"降级。

### 4.3 配置参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `scanner.workers` | `4` | 并发解析 worker 数 |
| `scanner.file_size_limit_mb` | `10` | 超过此大小的文件标记为 `parse_skipped` |
| `scanner.line_count_limit` | `50000` | 超过此行数的文件标记为 `parse_skipped` |
| `watcher.debounce_ms` | `300` | 防抖窗口（毫秒） |
| `watcher.queue_threshold` | `1000` | 队列阈值，超限触发全量扫描降级 |

## 5. Scanner 模块设计

```go
package scanner

type Scanner struct {
    store    *store.Store
    registry *parser.Registry
    workers  int
    semaphore chan struct{}
}

func NewScanner(store *store.Store, registry *parser.Registry, workers int) *Scanner {
    return &Scanner{
        store:     store,
        registry:  registry,
        workers:   workers,
        semaphore: make(chan struct{}, workers),
    }
}

// ScanAll 全量扫描仓库目录
func (s *Scanner) ScanAll(ctx context.Context, root string) error {
    files := listFiles(root)
    errCh := make(chan error, len(files))
    var wg sync.WaitGroup

    for _, file := range files {
        select {
        case <-ctx.Done():
            return ctx.Err()
        case s.semaphore <- struct{}{}:
        }
        wg.Add(1)
        go func(path string) {
            defer wg.Done()
            defer func() { <-s.semaphore }()
            errCh <- s.ProcessFile(ctx, path)
        }(file)
    }
    wg.Wait()
    close(errCh)
    return collectErrors(errCh)
}
```

## 8. 开发指南

### 8.1 实现步骤

1. **实现 Scanner worker pool**
   - 在 `internal/scanner/scanner.go` 中实现 `ScanAll` 方法。
   - 使用 semaphore channel 控制并发数（默认 4）。
   - 每个文件独立 goroutine + 独立事务。
   - 单测：mock store 和 registry，验证并发安全、错误收集。

2. **实现 Scheduler**
   - 在 `internal/scheduler/scheduler.go` 中实现防抖与排队。
   - 300ms 防抖窗口内合并相同文件路径。
   - 队列阈值 1000 触发全量扫描降级。
   - 单测：防抖合并、队列降级触发。

3. **实现 Watcher 防抖**
   - 在 `internal/watcher/watcher.go` 中实现 fsnotify 监听。
   - 集成 Scheduler 的排队逻辑。
   - 单测：mock fsnotify 事件，验证防抖、目录过滤、降级。

4. **并发安全测试**
   - 并发写入 `file` 表验证 `UNIQUE` 约束正确。
   - 同时运行全量扫描和增量监听验证互斥。
