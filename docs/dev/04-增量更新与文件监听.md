## 1. 概述

增量更新层负责检测文件变更、解析新内容并更新存储层，避免全量重建。核心机制包括：

- **SHA-256 哈希闸门**：文件级变更检测，未变化文件跳过解析。
- **行号区间匹配**：实体级增量更新（UPDATE / DELETE / INSERT），保留 ID 稳定，调用边不必全量重建。
- **fsnotify 文件监听**：实时捕获磁盘变更，防抖合并后按序处理。
- **跨文件依赖处理**：反向引用索引的局部重建与延迟批量重建。

## 2. 文件级变更检测（SHA-256 哈希闸门）

```go
func (s *Scanner) ProcessFile(ctx context.Context, path string) error {
    h := sha256sum(path)
    f, _ := s.store.GetFileByPath(ctx, path)
    if f != nil && f.ContentHash == h {
        return nil // 未变化，跳过
    }
    lang := detectLang(path)
    plugin, err := s.registry.Select(lang)
    if err != nil {
        return fmt.Errorf("select adapter for %s: %w", lang, err)
    }
    ir, err := plugin.Parse(ctx, path)
    if err != nil {
        return fmt.Errorf("parse %s: %w", path, err)
    }
    ir.FileHash = h
    ir.CommitHash = currentCommit()
    ir.ByteSize = statSize(path)
    ir.LineCount = countLines(path)
    // 注：ReferencedBy 的增量构建策略见 §5
    ir.ReferencedBy = s.buildReverseImportIndex(ctx, path)
    return s.store.InTx(ctx, func(tx *Tx) error {
        return upsertIR(tx, ir)
    })
}
```

**流程说明**：

1. 计算文件 SHA-256 哈希。
2. 查询 `file` 表，若 `content_hash` 一致则直接返回（跳过）。
3. 按语言选择适配器，解析文件得到 IR。
4. 填充元信息（哈希、commit、字节数、行数、反向引用）。
5. 在独立事务中执行 `upsertIR` 完成增量入库。

## 3. 行号区间匹配算法

### 3.1 核心思想

使用旧库 `(start_line, end_line)` 区间与新文件变更区间做交集，将实体分为保留、更新、删除三类。实体主键稳定，调用边不必全量重建。

### 3.2 区间重叠判定

```go
func intervalsOverlap(aStart, aEnd, bStart, bEnd int) bool {
    return aStart <= bEnd && bStart <= aEnd
}
```

### 3.3 upsertIR 伪代码

```
upsertIR(tx, ir):
    // 1. file 行：INSERT OR UPDATE，更新 content_hash / line_count / byte_size 等
    upsertFile(tx, ir)

    // 2. class 处理：按行号区间 + 名称匹配
    oldClasses = tx.GetClassesByFile(ir.FilePath)
    newClasses = ir.Classes

    for each newClass in newClasses:
        match = findMatch(oldClasses, newClass)
        if match 存在且区间重叠:
            tx.UpdateClass(match.id, newClass)     // 保留 id，刷新行号/签名/doc
        else if match 存在但区间不重叠:
            tx.UpdateClass(match.id, newClass)     // 重定位，更新行号
        else:
            tx.InsertClass(newClass)               // 新增

    for each oldClass in oldClasses:
        if oldClass 不在 newClasses 中:
            tx.DeleteClassCascade(oldClass.id)     // 级联删除 method/call/parameter

    // 3. method 处理：同 class 逻辑，匹配 (class_id, start_line, end_line, name)
    // 4. call 处理：先清空该文件旧调用边，再插入新边
    // 5. parameter / ret_type / tag 级联跟随 method ID 变更
```

### 3.4 匹配判定表

| 新 IR 实体 vs 旧库实体 | 判定 | 动作 |
|---|---|---|
| 行号区间重叠 + 名称一致 | 同一实体 | UPDATE（保留 id，刷新行号/签名/doc） |
| 旧库有 / 新 IR 无 | 已删除 | DELETE（级联清理子实体） |
| 新 IR 有 / 旧库无 | 新增 | INSERT |
| 区间不重叠但全限定名一致 | 重定位（rename/move） | UPDATE 行号（结合 git diff 行号平移辅助） |

## 4. 文件监听（fsnotify）

`internal/watcher` 模块使用 fsnotify 监听仓库文件变更，对标 CodeGraph 的 FSEvents/inotify + 防抖机制。

### 4.1 行为设计

```
cmd/codeschema watch ./repo 命令
行为：
1. 递归监听仓库目录下的文件变更事件
2. 变更事件入队，300ms 防抖窗口内合并相同文件的事件
3. 防抖窗口结束后，对变更文件调用 ProcessFile
4. 监听新增/删除/重命名文件，更新 file 表
5. 忽略 .git/ node_modules/ 等目录
```

### 4.2 配置参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `watcher.enabled` | `true` | 是否启用文件监听 |
| `watcher.debounce_ms` | `300` | 防抖窗口（毫秒） |
| `watcher.ignore_dirs` | `[".git", "node_modules", "target", "build"]` | 忽略的目录 |
| `watcher.batch_size` | `50` | 单批处理的最大文件数 |

## 5. 跨文件依赖处理

`buildReverseImportIndex` 构建"谁引用了本文件"的反向引用索引。增量场景下，每次改一个文件都重建全仓库反向引用代价过高，因此采用以下策略：

### 5.1 全量扫描时

一次性扫描所有文件的 import/include 语句，构建完整的反向引用映射。

### 5.2 增量更新时

- 仅对被修改文件及其直接依赖文件进行局部反向引用重算。
- 维护 `reverse_import_cache`（内存表或 Redis），记录每个文件的 import 列表和每个符号的被引用列表。
- 文件变更时，更新该文件自身的 import 列表，同时更新被引用文件的反向引用计数。

### 5.3 延迟批量重建（P2）

提供 `rebuild-refs` 命令，当局部索引偏差累积到阈值时，执行全量重建。

## 6. 开发指南

### 6.1 实现步骤

1. **实现 SHA-256 哈希函数**
   - 在 `internal/scanner/hash.go` 中实现 `sha256sum(path string) string`。
   - 使用 `os.ReadFile` + `crypto/sha256`，返回 hex 编码字符串。
   - 单测：空文件、大文件、二进制文件哈希一致性。

2. **实现 ProcessFile**
   - 在 `internal/scanner/scanner.go` 中实现 `ProcessFile` 方法。
   - 集成哈希闸门、适配器选择、IR 元信息填充、事务调用。
   - 单测：mock 适配器，验证哈希命中时跳过、哈希未命中时解析。

3. **实现 upsertIR**
   - 在 `internal/store/upsert.go` 中实现增量入库逻辑。
   - 实现 `intervalsOverlap` 函数和匹配判定表全部 4 种情况。
   - 实现级联删除（class 删除 → 级联清理 method / call / parameter）。
   - 单测：新增、修改、删除、重定位 4 种场景覆盖。

4. **实现 watcher 模块**
   - 在 `internal/watcher/watcher.go` 中实现 fsnotify 监听。
   - 实现防抖窗口（300ms）内合并相同文件事件。
   - 实现队列阈值（1000）触发全量扫描降级。
   - 单测：mock fsnotify 事件源，验证防抖合并、目录过滤、降级触发。

5. **实现 buildReverseImportIndex**
   - 在 `internal/scanner/import_index.go` 中实现反向引用构建。
   - 全量模式：扫描所有文件，构建完整映射。
   - 增量模式：局部更新 + 缓存维护。
