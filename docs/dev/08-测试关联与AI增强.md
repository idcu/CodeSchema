## 1. Tag 分类体系

Tag 采用多对多关联，可从注解、宏、包名等元数据自动推导。

| 分类 | 用途 | 示例 | 推导来源 |
|---|---|---|---|
| `layer` | 架构分层 | controller / service / dao / domain / infra | 包名/目录/注解 |
| `biz` | 业务域 | order / user / payment | 业务包/目录 |
| `tech` | 技术特征 | cache / mq / retry / transactional | 注解/import |
| `risk` | 风险标记 | legacy / todo / performance | TODO 注释/AI 标注 |
| `test` | 测试类型 | unit / integration | 文件路径/注解 |
| `lang` | 语言 | go / java / cpp | 文件语言 |

### 1.1 Tag 表 DDL

```sql
CREATE TABLE tag (
  id INTEGER PRIMARY KEY,
  name TEXT UNIQUE,
  category TEXT
);

CREATE TABLE class_tag (
  class_id INTEGER,
  tag_id INTEGER,
  PRIMARY KEY(class_id, tag_id)
);

CREATE TABLE method_tag (
  method_id INTEGER,
  tag_id INTEGER,
  PRIMARY KEY(method_id, tag_id)
);
```

## 2. 测试关联策略

### 2.1 策略定义

| 策略 | 置信度 | 说明 | 实现状态 |
|---|---|---|---|
| `explicit` | 100 | 显式注解（如 `@TestFor(OrderService.class)`） | ✅ 已实现 |
| `naming` | 70 | 命名约定（`OrderServiceTest` ↔ `OrderService`） | ✅ 已实现 |
| `coverage` | 90 | 覆盖率数据反查覆盖方法 | ✅ 已实现 |
| `same_tag` | 60 | 同 Tag 聚类（同 `biz:order` 等） | ✅ 已实现 |
| `dependency` | 80 | 导入依赖递归：改业务方法 → 递归追踪 import/include 依赖 → 关联依赖方单测；C/C++ 头文件改动经 `file.referenced_by_files` 定位受影响 .cpp 单测 | ✅ 已实现 |

### 2.2 关联表 DDL

```sql
CREATE TABLE method_test_link (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  method_id INTEGER,
  test_method_id INTEGER,
  strategy TEXT,                         -- explicit / naming / coverage / same_tag / dependency
  confidence INTEGER DEFAULT 70,
  UNIQUE(method_id, test_method_id)
);
CREATE INDEX idx_mtl_method ON method_test_link(method_id);
CREATE INDEX idx_mtl_test ON method_test_link(test_method_id);
```

### 2.3 查询示例

```sql
-- 查某方法的关联单测（按置信度排序）
SELECT m.full_name AS test_method, l.strategy, l.confidence
FROM method_test_link l
JOIN method m ON m.id = l.test_method_id
WHERE l.method_id = (SELECT id FROM method WHERE full_name = 'com.x.OrderService')
ORDER BY l.confidence DESC;

-- 无单测覆盖预警
SELECT c.full_name FROM class c
WHERE NOT EXISTS (
  SELECT 1 FROM method_test_link l
  JOIN method m ON m.id = l.method_id
  WHERE m.class_id = c.id
);

-- 改头文件 → 经 referenced_by_files 找受影响源文件 → 关联其单测
SELECT f.relative_path AS affected_source
FROM file f, json_each(f.referenced_by_files) ref
WHERE ref.value = 'src/include/order.h';
```

### 2.4 单测定界

方法 `(start_line, end_line)` + 改动行号区间 → 反查受影响方法（dependency 策略经 import/include 图递归）→ 关联单测（按置信度排序）→ CI 只跑相关单测。`file.byte_size` / `file.line_count` 用于大文件旁路，避免对超大文件做整文件读取。

## 3. AI 增强层设计

### 3.1 设计原则

- **按需触发**：实体缺 Tag、doc 残缺、调用目标模糊、跨语言边界时触发。
- **失败隔离**：AI 调用失败 → 记录日志 → 继续主流程，索引始终可用。
- **预算硬限**：每次扫描/查询的 AI 调用次数受预算管控，超限跳过。

### 3.2 Enhancer 实现

```go
// internal/ai/enhancer.go
package ai

type Enhancer struct {
    client LLMClient
    budget Budget
}

// EnhanceTag 对实体推导并补全标签。
func (e *Enhancer) EnhanceTag(ctx context.Context, ent IRable) ([]string, error) {
    if !e.budget.TryConsume() {
        return nil, ErrBudgetExceeded
    }
    return e.client.Complete(ctx, buildTagPrompt(ent))
}

// EnhanceDoc 为残缺的 doc_comment 生成补充描述。
func (e *Enhancer) EnhanceDoc(ctx context.Context, ent IRable) (string, error) {
    if !e.budget.TryConsume() {
        return "", ErrBudgetExceeded
    }
    return e.client.Complete(ctx, buildDocPrompt(ent))
}

// Disambiguate 对同名方法进行消歧，返回匹配的索引 ID。
func (e *Enhancer) Disambiguate(ctx context.Context, candidates []MethodIR, hint string) (int, error) {
    if !e.budget.TryConsume() {
        return 0, ErrBudgetExceeded
    }
    return e.client.Choose(ctx, buildDisambiguationPrompt(candidates, hint))
}
```

### 3.3 预算管控

- `config.ai.budget_per_scan`：每次扫描的 AI 调用次数硬限。
- `config.ai.budget_per_query`：每次查询的 AI 调用次数硬限。
- 超限后跳过本次增强，不影响主流程。
- 预算计数器在每次扫描/查询开始时重置。

### 3.4 失败语义

AI 调用失败（超时、服务不可用、预算超限）不影响主流程。记录日志后继续执行，索引始终可用。
