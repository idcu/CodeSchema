## 1. 设计原则

1. **核心不依赖任何具体解析器**——编译期可剔除任意适配器。
2. **只定义 `ParserPlugin` 接口与统一 `IRDocument`**——所有解析能力以适配器身份接入。
3. **适配器可独立编译、测试、启停**，数据来源可追溯（`source` 字段）。
4. **竞品是"被集成的上游数据源"**——通过消费其产出（SQLite / SCIP index）接入，不内嵌其代码；源不可用时自动降级到 tree-sitter/SCIP。

## 2. IR 结构体定义

```go
// internal/parser/ir.go
package parser

import "context"

// IRDocument 是一次解析的归一化产出。
type IRDocument struct {
    Source      string   // 数据来源标识，如 "treesitter" / "scip-java" / "codegraph"
    Language    string   // "go" / "java" / "cpp" / "ts" / "py" / "rust"
    FilePath    string
    FileHash    string   // SHA-256，由编排层填充
    CommitHash  string   // git commit，由编排层填充
    LineCount   int      // 文件总行数（编排层统计）
    ByteSize    int64    // 文件字节大小（编排层 os.Stat）
    ReferencedBy []string // 引用本文件的文件清单（import/include 反向）
    Classes    []ClassIR
    Methods    []MethodIR
    Calls      []CallIR
    Imports    []string  // 文件级 import，辅助跨模块/测试关联
}

type ClassIR struct {
    Name         string
    FullName     string
    Type         string   // CLASS / INTERFACE / ABSTRACT / ENUM
    ParentFQNs   []string // 父类/接口全限定名
    StartLine, StartCol, EndLine, EndCol int
    Modifier     string
    Doc          string
    Annotations  []string
    Extra        map[string]any // 语言差异兜底（JSONB）
}

type MethodIR struct {
    Name, Signature, ReturnType string
    ClassFQN   string
    StartLine, StartCol, EndLine, EndCol int
    Modifier   string
    Doc        string
    Annotations []string
    IsStatic, IsAbstract, IsConstructor bool
    Params     []ParamIR
    Extra      map[string]any
}

type ParamIR struct {
    Name, Type string
    Index      int
    Annotation string
}

type CallIR struct {
    CallerFQN, CalleeFQN string
    CallType  string // direct / interface / dynamic / unknown
    LineNumber int
}
```

## 3. ParserPlugin 接口定义

适配器接口设计区分两类不同语义的适配器：

- **文件级适配器**（tree-sitter、LSP 子进程）：按单个文件解析，`Parse(ctx, path)` 语义自然匹配。
- **批量适配器**（SCIP index、CodeGraph/JCodeIndexer SQLite）：消费整个 index 产出，需按文件分发或全量导入。

```go
// ParserPlugin 是所有适配器的统一契约。
// 文件级适配器（tree-sitter、LSP）实现 Parse 方法。
// 批量适配器（SCIP、CodeGraph、JCodeIndexer）应实现 BatchParser 子接口。
type ParserPlugin interface {
    // Name 返回适配器唯一标识。
    Name() string
    // Supports 判断适配器是否支持指定语言。
    Supports(lang string) bool
    // Init 初始化适配器（如启动 LSP 子进程、加载 index 文件）。
    // 在注册后、首次使用前调用一次；返回 nil 表示初始化成功。
    Init(ctx context.Context, config map[string]any) error
    // Close 清理适配器资源（如关闭子进程、释放文件句柄）。
    Close() error
    // Parse 解析单个文件，返回归一化 IR。
    // err == nil 且 IR 为空表示跳过该文件。
    Parse(ctx context.Context, path string) (*IRDocument, error)
}

// BatchParser 是批量适配器的扩展接口。
// 消费 SCIP index 文件、竞品 SQLite 数据库的适配器应实现此接口。
type BatchParser interface {
    ParserPlugin
    // ParseAll 批量解析，返回所有文件 IR 的迭代器通道。
    // 调用方可通过 context 取消，适配器应在取消时关闭 channel。
    ParseAll(ctx context.Context, paths []string) (<-chan *IRDocument, error)
}
```

## 4. Registry 注册中心实现

```go
// internal/parser/registry.go
package parser

import "fmt"

type Registry struct {
    plugins      []ParserPlugin
    priorityMap  map[string][]string // language -> ordered adapter names
}

func NewRegistry() *Registry {
    return &Registry{
        priorityMap: make(map[string][]string),
    }
}

func (r *Registry) Register(p ParserPlugin) {
    r.plugins = append(r.plugins, p)
}

// SetPriority 为指定语言设置适配器优先级顺序。
// 如未设置，默认按注册顺序。
func (r *Registry) SetPriority(lang string, names []string) {
    r.priorityMap[lang] = names
}

// Select 按语言选择优先级最高的可用适配器。
// 优先级：SCIP > LSP > 竞品直读 > tree-sitter（默认），配置可覆盖。
func (r *Registry) Select(lang string) (ParserPlugin, error) {
    priorities, hasPriority := r.priorityMap[lang]
    if hasPriority {
        for _, name := range priorities {
            for _, p := range r.plugins {
                if p.Name() == name && p.Supports(lang) {
                    return p, nil
                }
            }
        }
    }
    // 默认：按注册顺序取第一个匹配的
    for _, p := range r.plugins {
        if p.Supports(lang) {
            return p, nil
        }
    }
    return nil, fmt.Errorf("no adapter found for language: %s", lang)
}
```

## 5. 适配器实现清单

| 适配器 | 输入 | 产出 IR 覆盖 | 代码量估计 | 说明 |
|---|---|---|---|---|
| `treesitter` | 源文件 | class/method + 行号 + 简单调用名（24 语言：go/java/ts/py/rust/cpp/c/kotlin/swift/php/csharp/ruby/bash/scala/sql/elixir/ocaml/lua/groovy/css/toml/yaml/protobuf/html） | ~400 行 | 通用兜底，纯 Go 正则启发式，无 CGO；调用检测已全语言启用 |
| `scip` | SCIP index 文件（批量） | class/method + 精确引用边 | ~200 行 | 消费 scip-java/go/clang 产出；首选精确数据源；流式加载 + 文档背压 |
| `jdtls` | Java 文件（LSP 子进程） | 符号 + references | ~400 行 | 需 JDK，P1 接入 |
| `clangd` | C/C++ 文件（LSP 子进程） | 符号 + references | ~400 行 | 需 compile_commands.json |
| `gopls` | Go 文件（LSP 子进程） | 符号 + references | ~300 行 | Go 官方 LSP |
| `codegraph` | CodeGraph SQLite（批量） | 直接读 symbols/edges 表 | ~200 行 | 竞品产出直读；源不可用降级 tree-sitter |
| `jcodeindexer` | JCodeIndexer SQLite（批量） | 直接读其符号表 | ~200 行 | 竞品产出直读；源不可用降级 tree-sitter |

> 精度档位：`treesitter` 为正则启发式（T2-1 方案 C 的默认档，免 CGO）；真语法树（CGO tree-sitter）按
> `-tags treesitter` 隔离为可选项，方案评估见 `analysis/2026-08-14-t2-1-parser-precision-eval.md`。

每个适配器为独立子包 `internal/parser/adapter/<name>`，可单独编译测试。许可证边界：系统仅消费产出（SQLite/SCIP index）或通过子进程调用 LSP，不内嵌任何竞品代码。

## 6. 按语言择优方案

| 语言 | 首选方案 | 精确语义 | 兜底方案 |
|---|---|---|---|
| 通用多语言 | tree-sitter（CGO，`-tags treesitter` 可选项） | 语法级 | 正则启发式（默认） |
| Go | gopls（官方 LSP） | 是 | tree-sitter |
| Java / Scala / Kotlin | JCodeIndexer SQLite 直读 + jdtls + scip-java | 是 | tree-sitter |
| Kotlin（无 index 时） | tree-sitter 正则 | 否（启发式） | — |
| C / C++ | clangd + scip-clang | 是 | tree-sitter |
| TypeScript / JavaScript | scip-typescript / tsserver | 是 | tree-sitter |
| Python | scip-python / pyright | 是 | tree-sitter |
| Rust | rust-analyzer（LSP） | 是 | tree-sitter |

## 7. 统一 IR 约定

1. **语言无关**：所有适配器产出同一 IR 结构；语言差异进 `Extra map[string]any`（落库为 JSONB），不改表结构。
2. **稳定主键**：实体业务主键使用 `(file_id, full_name, start_line)` 候选键；数据库自增 `id` 为内部主键，跨版本映射以 git diff 行号平移辅助，绝不拿旧行号硬跨版本匹配。
3. **来源可追溯**：`IRDocument.Source` 传递至 `class.source`、`method.source`、`call.source`，便于排查与回滚。
4. **文件元信息随 IR 流转**：`LineCount`、`ByteSize`、`ReferencedBy` 由编排层一次性填充进 IR，入库时写入 `file` 表扩展字段。

## 8. 降级与容错策略

- 竞品直读适配器（CodeGraph / JCodeIndexer）在源数据库不可用时，自动降级到 tree-sitter 或 SCIP 适配器。
- 降级逻辑由注册中心的 `Select` 方法实现：当前适配器 `Parse` 返回特定错误（`ErrSourceUnavailable`）时，编排层调用 `Select` 获取下一个可用适配器重试。
- P3 阶段需通过健壮性测试覆盖降级路径，验证降级后索引质量不低于阈值。
- **LSP 适配器健壮性（T2-3，已落地）**：LSP 子进程的失败与降级原因须可观测，禁止"静默丢信息"。具体措施（`internal/parser/adapter/lsp/adapter.go`）：
  - **项目上下文探测**：clangd 在 `Init` 时显式探测 `compile_commands.json`（根目录及 `build`/`cmake-build-debug`/`out`/`.cache/clangd`），缺失则 WARN 并计入 `lsp_missing_compile_commands_total`，避免"缺项目上下文→静默空符号"。
  - **失败重试**：`documentSymbol` 等高频请求经 `requestWithRetry` 包裹（复用 `robust.Retry` 指数退避 + `robust.RetryableError` 判定），仅对瞬时错误（超时/连接重置）重试，不放大单文件延迟。
  - **空符号告警**：解析非空 C/C++ 文件却得到 0 符号时显式 WARN + `lsp_parse_empty_symbols_total{lang="cpp"}`。
  - **协议帧可观测**：`readResponses` 中原静默丢弃的异常帧（Content-Length 解析失败 / JSON 体解析失败 / 孤儿响应）改为 WARN + `lsp_malformed_frames_total{kind=...}`。
  - **子进程 stderr 暴露**：clangd 等写到 stderr 的降级/错误原因（如缺 `compile_commands.json`）由 `io.Discard` 改为按行日志（关键字 WARN，其余 DEBUG）。

## 9. 开发指南

1. **创建 parser 包**：在 `internal/parser` 下创建 `ir.go`，定义 `IRDocument`、`ClassIR`、`MethodIR`、`ParamIR`、`CallIR` 结构体。
2. **定义接口**：在 `internal/parser/plugin.go` 中定义 `ParserPlugin` 接口和 `BatchParser` 子接口。
3. **实现注册中心**：在 `internal/parser/registry.go` 中实现 `Registry` 结构体，包含 `Register`、`SetPriority`、`Select` 方法。
4. **编写单元测试**：
   - 创建 mock 适配器（实现 `ParserPlugin` 接口）。
   - 测试 `Registry.Select` 按优先级返回正确适配器。
   - 测试无匹配适配器时返回错误。
   - 测试 `SetPriority` 覆盖默认顺序。
5. **创建适配器骨架**：为 `treesitter` 和 `scip` 创建 `internal/parser/adapter/<name>` 子包，实现 `ParserPlugin` 接口（Init/Close 可先返回 nil）。
6. **编写降级路径测试**：验证 `Select` 在首选适配器不可用时的回退行为。
