## 1. 完整配置模型

```yaml
# config.yaml — 完整配置项
project:
  name: myrepo                    # 项目名称
  root: ./repo                    # 仓库根路径
  languages: [go, java, cpp, ts]  # 目标语言列表

storage:
  driver: sqlite                  # sqlite（P0）| postgres（P2）
  dsn: ./codeschema.db            # 数据库连接串
  kv: redis://localhost:6379/0    # P2 启用，Redis 连接串
  vector:
    driver: chromem               # chromem | milvus-lite | milvus
    dsn: ./vector.db              # 向量库路径/连接串
    embedding_model: bge-small-zh # Embedding 模型
  search:
    fts: true                     # 启用 FTS5 全文搜索
    semantic: true                # P2 启用，语义检索

parser:
  adapters: [scip, treesitter, codegraph, jcodeindexer]  # 启用的适配器列表
  scip:
    index_dir: ./scipout          # SCIP index 输出目录
  codegraph:
    db: ./codegraph.db            # CodeGraph SQLite 路径
  jcodeindexer:
    db: ./jcodeindexer.db         # JCodeIndexer SQLite 路径
    config_file: .jindexer/config.yaml  # 兼容 JCI 配置约定
    env:
      INDEXER_EMBEDDING_ENABLED: "false"

ai:
  provider: openai                # openai | anthropic | local
  model: gpt-4o-mini              # LLM 模型名
  budget_per_scan: 100            # 每次扫描 AI 调用硬限
  budget_per_query: 10            # 每次查询 AI 调用硬限

server:
  mcp_addr: ":8080"               # MCP Server 监听地址
  http_addr: ":8081"              # HTTP API 监听地址
  auth_token: ""                  # 空字符串表示不启用认证

watcher:
  enabled: true                   # 是否启用文件监听
  debounce_ms: 300                # 防抖窗口（毫秒）
  ignore_dirs: [".git", "node_modules", "target", "build"]  # 忽略的目录
  batch_size: 50                  # 单批处理的最大文件数

scanner:
  workers: 4                      # 并发解析 worker 数
  file_size_limit_mb: 10          # 超过此大小的文件标记为 parse_skipped
  line_count_limit: 50000         # 超过此行数的文件标记为 parse_skipped
```

## 2. 部署形态

| 阶段 | 部署形态 | 依赖 |
|---|---|---|
| P0 MVP | 单二进制（Go 编译），SQLite 零配置 | 无外部依赖 |
| P1 | 单二进制 + SQLite | 可选：LSP 子进程、SCIP indexer |
| P2 | 单二进制 + PostgreSQL + Redis + 向量库 | Docker Compose |
| P3 | 容器化部署，可水平扩展 | Kubernetes（可选） |

## 4. P0-P3 详细路线图

### 4.1 P0 骨架（2 周）

**交付物**：Go 项目骨架 + `ParserPlugin` 接口 + 注册中心 + SQLite DDL + 基础 CLI

**关键里程碑**：
- Go 项目初始化，模块结构搭建
- `ParserPlugin` 接口和 `IRDocument` 结构体定义
- 注册中心 `Registry` 实现
- SQLite DDL 建表（project/file/class/method/parameter/call）
- 基础 CLI 命令框架（`scan`/`serve`/`version`）

### 4.2 P0 MVP（3-5 周）

**交付物**：tree-sitter adapter + CodeGraph SQLite 直读 adapter + MCP 工具（context/impact/tests/affected）+ fsnotify 文件监听 + 增量更新

**关键里程碑**：
- tree-sitter 适配器实现（通用兜底）
- CodeGraph SQLite 直读适配器实现
- 增量更新（行号区间匹配 + 哈希闸门）
- fsnotify 文件监听（300ms 防抖）
- MCP Server 实现（4 个核心工具）
- 可用系统，可索引仓库并通过 MCP 查询

### 4.3 P1 精确语义（4-6 周）

**交付物**：SCIP adapter + LSP adapter + JCodeIndexer 直读 + 测试关联 dependency 策略 + 7 仓库 benchmark + 降级兜底测试

**关键里程碑**：
- SCIP 适配器实现（java/go/clang）
- LSP 适配器实现（jdtls/clangd）
- JCodeIndexer SQLite 直读适配器
- 测试关联 dependency 策略实现
- 降级路径验证（源不可用自动降级）
- 7 仓库 benchmark 完成，出 median 报告

### 4.4 P2 差异化（4-6 周）

**交付物**：Tag 体系 + AI 增强（预算管控）+ 向量语义检索 + MCP 工具扩至 8-10 + PostgreSQL/Redis 迁移 + FTS5

**关键里程碑**：
- Tag 体系落地（六类标签自动推导）
- AI 增强层（Enhancer + 预算管控）
- 向量语义检索（chromem-go + bge-small-zh）
- FTS5 全文搜索 + 双路融合重排
- PostgreSQL/Redis 迁移支持
- MCP 工具扩至 8-10

### 4.5 P3 扩展（持续）

**交付物**：TypeScript/Python/Rust adapter + Cypher/GraphQL 图查询 + 多语言扩展 + 生产级健壮性

**关键里程碑**：
- 全语言覆盖
- 图查询出口（Cypher/GraphQL）
- 生产级健壮性测试
- 实测降本数据持续积累

## 5. 实测对标方案

### 5.1 步骤

1. **仓库选取**：7 个真实开源仓库（覆盖 Go/Java/TypeScript，规模 1k–50k 文件），与 CodeGraph benchmark 仓库尽量重叠。
2. **指标采集**：每次问答采集 `prompt_token`、`completion_token`、`tool_call_count`、`latency_ms`；分别统计有/无本系统裁剪两组。
3. **口径**：`token_saving = 1 - tokens_with_system / tokens_without_system`（median，跨 7 仓库）；`tool_call_reduction`、`cost_reduction` 同口径。
4. **输出**：`codeschema benchmark ./repo` 生成报告（markdown + csv），含每仓库原始值与 7 仓库 median，与 CodeGraph 数据并列呈现。
5. **门槛**：若实测 `token_saving_median < 90%`，触发检索/裁剪策略复盘（先查召回率，再调裁剪窗口）。

## 6. 风险识别与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 单维护者风险外溢（CodeGraph 约 91% 单人维护） | CodeGraph 停更 → 直读适配器失效 | 直读适配器始终保留 tree-sitter/SCIP 降级路径；P3 健壮性测试覆盖 |
| 工作量低估 | P0 排期失控 | 工期修正为 5-7 周；骨架（2 周）与可用 MVP（3-5 周）拆为两个里程碑 |
| 实测数据缺失 | token 节省仅为理论值 | P1 完成 7 仓库 benchmark，出 median 报告 |
| MCP 互操作未对齐 | Agent 接入需适配，迁移成本高 | 工具命名/语义对齐 CodeGraph + JCodeIndexer 事实标准 |
| 语义检索未落地 | 模糊/跨文件语义查询偏弱 | P2 落地 chromem-go + bge-small-zh，FTS5 + 向量双路 |
| 许可证合规 | 内嵌竞品代码引发合规风险 | 仅消费产出或子进程调用 LSP，不内嵌任何竞品代码 |
| 大文件/生成文件污染索引 | 索引膨胀、AI 整文件读取超时 | `byte_size`/`line_count` 阈值旁路；`parse_status='parse_skipped'` 留痕 |
| 行号跨版本漂移 | rename/move 后实体匹配失败 | 区间重叠 + 全限定名兜底；git diff 行号平移辅助；主键不依赖行号 |
| 跨文件反向引用增量性能 | 每次文件变更触发全量扫描 | 局部反向引用重算 + 延迟批量重建策略 |
