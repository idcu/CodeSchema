## 1. 系统定位

**CodeSchema** 是一个**面向 AI 辅助开发的代码元数据索引与上下文裁剪服务**。它将仓库中的类、方法、接口、继承关系、调用关系、文件路径、行号、参数、返回值、用途标签等结构化数据，沉淀为「关系型数据库（权威源）+ KV 缓存（热读）+ 向量索引（语义检索）」三层存储，并通过 MCP Server 向 AI Agent 供给**精准裁剪后的代码上下文**，从而：

- 让 AI 回答"某类/某方法在哪、干什么、谁调用它"时，**不必喂入整个仓库**，大幅节省 token 消耗。
- 改一行代码即可反查受影响方法并定位其关联单测，**只跑相关单测**，节省开发与 CI 时间。
- 以「符号图精确检索 + 向量语义检索」双路模式，服务代码理解、影响面分析、文档生成、重构与逆向工程。

---

## 2. 设计目标

| 指标 | 目标值 | 说明 |
|---|---|---|
| 单文件解析延迟（P95） | < 20 ms | 解析由外接适配器完成，Go 只做编排与入库 |
| AI 上下文 token 节省 | 理论 99.7%；P1 替换为 7 仓库实测区间 | 50 万行仓库问答从 ~150K token 降到数百 token |
| AI 增强成本占比 | < 总运行成本 5% | AI 仅按需校验/补全，受预算硬限约束 |
| 增量同步 | 文件级哈希闸门 + 行号区间匹配 + fsnotify 文件监听 | 保留实体主键，调用边不必全量重建 |
| 多语言 | Go / Java / C++ / TypeScript / Python / Rust（渐进式） | 按语言择优选择不同解析源 |
| 实测对标 | P1 完成 7 仓库 benchmark | 与 CodeGraph 同款仓库/口径对比，出 median 报告 |

---

## 3. 非目标范围

- **不自研多语言 AST / 类型系统 / 语义分析**——解析 100% 外包给 tree-sitter / LSP / SCIP indexer / 竞品产出。
- 不做通用搜索引擎（不重复建设 Sourcegraph 类产品）。
- 不让 AI 承担主解析——AI 仅作为校验器、补全器、兜底器，不是主路径。

---

## 4. 技术选型策略与竞品定位

**核心策略：解析外包 + 应用层差异化，而非另起炉灶。**

本系统不直接与现有竞品竞争，而是将其作为**上游数据源**进行消费，在其成熟范式之上叠加差异化能力：

- **CodeGraph**（MIT，21 语言）：验证了"tree-sitter 结构图 + MCP + 文件监听增量"范式。其单维护者风险通过直读适配器 + tree-sitter/SCIP 降级路径规避。
- **JCodeIndexer**（Apache-2.0）：证明 JVM 专项（Java/Kotlin/Scala + 30+ 框架注解）可做到精确符号/调用图/配置搜索，其 SQLite 产出与 MCP 工具集值得复用与命名对齐。
- **SCIP / Sourcegraph**（各语言均 GA）：提供编译器级精确索引协议，应作为**首选精确数据源**消费。
- **code-graph-rag / code-context-mcp**：补齐"图 + RAG / 语义 / 仓库地图"能力，提示本系统 P2 应补向量语义检索。

**结论**：竞品是"被集成的上游数据源"，不是对手。本系统在其成熟范式（MCP + SQLite + tree-sitter/SCIP）之上，叠加它们没有的 **Tag 体系 + 测试关联五策略 + AI 裁剪 + token 预算管控 + 语义检索**，形成不可替代的差异化价值。

## 6. 数据流设计

系统包含三条数据流：

1. **正向建索引**：源码文件 → 适配器解析 → 统一 IR → 存储层写入（SQLite/PG + Redis + 可选向量 + 全文检索）。
2. **增强按需**：对缺 Tag、残缺实体、模糊调用，AI 按预算补全，失败不影响主流程。
3. **反向服务 AI**：Agent 通过 MCP/HTTP 查询 → 存储层 + 裁剪层 → 返回精准上下文给 LLM。

## 7. 模块化拆分（M1-M6）

| 模块 | 包路径 | 职责 | 依赖 |
|---|---|---|---|
| M1 接入层 | `cmd/` + `internal/server` | CLI、HTTP、MCP Server（8–10 工具） | M6 |
| M2 编排层 | `internal/scanner` + `internal/scheduler` + `internal/watcher` | 扫描、调度、增量、事务、fsnotify 文件监听 | M3、M6 |
| M3 解析适配中间层 | `internal/parser` + `internal/parser/adapter/*` | 解析插件注册中心 + 各适配器实现 | 无（仅 IR 接口） |
| M4 AI 增强层 | `internal/ai` | Tagger、补全、消歧，预算管控 | M6 |
| M5 存储层 | `internal/store` + `internal/kv` + `internal/vector` + `internal/search` | 数据库、KV、向量读写、全文检索（PersistentFTS） | 数据库驱动 |
| M6 服务层 | `internal/service` | 查询、裁剪、测试关联、影响面分析 | M5 |

**模块耦合规则**：M3 内部除统一 IR 定义外，不依赖任何具体解析器。各适配器以独立子包存在，可单独编译、测试、启停。M4 对 M3 产物（IR）操作，不直接调用任何解析器。竞品直读适配器在源不可用时自动降级到 tree-sitter/SCIP。

## 8. 模块依赖与构建约束

```
cmd/codeschema ──► M1(internal/server) ──► M6(internal/service)
                                         ▲
M2(internal/scanner/scheduler/watcher) ──┤
M3(internal/parser + adapter/*) ─────────┤──► M5(internal/store/kv/vector/search)
M4(internal/ai) ─────────────────────────┘
```

| 模块 | 可独立 `go build` | 独立测试 | 说明 |
|---|---|---|---|
| M3 `internal/parser` | 是（除 IR 定义外无具体解析器依赖） | 是 | 每适配器独立 `*_test.go` |
| M3 各 `adapter/<name>` | 是 | 是 | 可单独编译/启停，降级路径单测覆盖 |
| M2 `internal/watcher` | 是 | 是 | fsnotify 防抖单测 |
| M4 `internal/ai` | 是 | 是（mock LLMClient） | 预算管控独立可测 |
| M5 `internal/vector` | 是（chromem-go 嵌入式） | 是 | 嵌入/检索单测 |
| M6 `internal/service` | 依赖 M5 | 是 | 服务层单测 |

**构建原则**：M3 不 import 任何具体适配器实现。适配器通过 `Register()` 注入注册中心。新增语言只需新增一个 adapter 子包 + 注册，不改核心代码（开闭原则）。

## 9. 开发阶段规划

| 阶段 | 周期（单人） | 交付物 | 关键里程碑 |
|---|---|---|---|
| **P0 骨架** | 2 周 | Go 项目骨架 + `ParserPlugin` 接口 + 注册中心 + SQLite DDL + 基础 CLI | 可编译运行，单文件解析入库 |
| **P0 MVP** | 3–5 周 | tree-sitter adapter + CodeGraph SQLite 直读 adapter + MCP 工具（context/impact/tests/affected）+ fsnotify 文件监听 + 增量更新 | 可用系统，可索引仓库并通过 MCP 查询 |
| **P1 精确语义** | 4–6 周 | SCIP adapter（java/go/clang）+ LSP adapter（jdtls/clangd）+ JCodeIndexer SQLite 直读 + 测试关联 dependency 策略 + 7 仓库 benchmark + 降级兜底测试 | 实测 token 节省数据；竞品源不可用自动降级验证 |
| **P2 差异化** | 4–6 周 | Tag 体系 + AI 增强（预算管控）+ 向量语义检索（chromem-go + bge-small-zh）+ MCP 工具扩至 8–10 + PostgreSQL/Redis 迁移 + 全文检索 | 语义检索落地；图查询出口 Cypher/GraphQL |
| **P3 扩展** | 持续 | TypeScript/Python/Rust adapter + Cypher/GraphQL 图查询 + 多语言扩展 + 降级兜底测试 + 实测降本数据持续积累 | 全语言覆盖；生产级健壮性 |
