## 1. 概述

适配器层是系统的核心扩展点，通过 `ParserPlugin` 接口接入多种解析源。P0 优先实现 tree-sitter（通用兜底）和 CodeGraph 直读（竞品产出复用），P1 逐步接入 SCIP、LSP、JCodeIndexer。

## 2. 适配器实现清单

| 适配器 | 输入 | 产出 IR 覆盖 | 代码量估计 | 说明 |
|---|---|---|---|---|
| `treesitter` | 源文件 | class/method + 行号 + 简单调用名（22 语言：go/java/ts/py/rust/cpp/c/kotlin/swift/php/csharp/ruby/bash/scala/sql/elixir/ocaml/lua/groovy/css/toml/yaml） | ~400 行 | 通用兜底，纯 Go 正则启发式，无 CGO；调用检测已全语言启用 |
| `scip` | SCIP index 文件（批量） | class/method + 精确引用边 | ~200 行 | 消费 scip-java/go/clang 产出；首选精确数据源；流式加载 + 文档背压 |
| `jdtls` | Java 文件（LSP 子进程） | 符号 + references | ~400 行 | 需 JDK，P1 接入 |
| `clangd` | C/C++ 文件（LSP 子进程） | 符号 + references | ~400 行 | 需 compile_commands.json |
| `gopls` | Go 文件（LSP 子进程） | 符号 + references | ~300 行 | Go 官方 LSP |
| `codegraph` | CodeGraph SQLite（批量） | 直接读 symbols/edges 表 | ~200 行 | 竞品产出直读；源不可用降级 tree-sitter |
| `jcodeindexer` | JCodeIndexer SQLite（批量） | 直接读其符号表 | ~200 行 | 竞品产出直读；源不可用降级 tree-sitter |

每个适配器为独立子包 `internal/parser/adapter/<name>`，可单独编译测试。系统仅消费产出（SQLite/SCIP index）或通过子进程调用 LSP，不内嵌任何竞品代码。

> 新增语言（Kotlin/Swift/PHP 已落地）扩展步骤：① `adapter.ExtToLang` 增加扩展名映射（如 `.kt`/`.kts` → `kotlin`、`.swift` → `swift`、`.php` → `php`）；
> ② `internal/parser/adapter/treesitter/initPatterns` 增加 `langPatterns`（class/method/call 正则 + commentTrim）；
> ③ `scanner.detectLang` 与 `adapter.SupportedLanguages`/`LangToExtensions` 同步；④ 补 Parse 测试。
> 精度档位与 tree-sitter 真语法树（CGO）方案评估见 `analysis/2026-08-14-t2-1-parser-precision-eval.md`。

## 3. 按语言择优方案

| 语言 | 首选方案 | 精确语义 | 兜底方案 |
|---|---|---|---|
| 通用多语言 | tree-sitter（CGO，`-tags treesitter` 可选项） | 语法级 | 正则启发式（默认） |
| Go | gopls（官方 LSP） | 是 | tree-sitter |
| Java / Scala / Kotlin | JCodeIndexer SQLite 直读 + jdtls + scip-java | 是 | tree-sitter |
| Kotlin（无 index 时） | tree-sitter 正则 | 否（启发式） | — |
| C / C++ | clangd + scip-clang | 是 | tree-sitter |
| TypeScript / JavaScript | scip-typescript / tsserver | 是 | tree-sitter |
| Python | scip-python / pyright | 是 | tree-sitter |
| Rust | rust-analyzer（LSP） | 是 | tree-sitter |

## 4. 降级策略

### 4.1 降级触发条件

竞品直读适配器（CodeGraph / JCodeIndexer）在源数据库不可用时，自动降级到 tree-sitter 或 SCIP 适配器。

### 4.2 降级实现

降级逻辑由注册中心的 `Select` 方法实现：

```
当前适配器 Parse 返回 ErrSourceUnavailable
  → 编排层调用 registry.Select(lang) 获取下一个可用适配器
  → 重试解析
  → 最多降级 1 次
```

### 4.3 降级路径

```
CodeGraph SQLite 不可用 → tree-sitter (或 SCIP)
JCodeIndexer SQLite 不可用 → tree-sitter (或 SCIP)
LSP 子进程启动失败 → tree-sitter
```

## 5. tree-sitter 适配器实现指南

### 5.1 接口实现

```go
package adapter_treesitter

type TreeSitterAdapter struct {
    parser *sitter.Parser // tree-sitter Go binding
}

func (a *TreeSitterAdapter) Name() string { return "treesitter" }
func (a *TreeSitterAdapter) Supports(lang string) bool { /* 按语言返回 */ }
func (a *TreeSitterAdapter) Init(ctx context.Context, config map[string]any) error { /* 初始化 parser */ }
func (a *TreeSitterAdapter) Close() error { /* 清理 */ }
func (a *TreeSitterAdapter) Parse(ctx context.Context, path string) (*parser.IRDocument, error) { /* 核心逻辑 */ }
```

### 5.2 关键步骤

1. 使用 `go-tree-sitter` 绑定创建 parser 实例。
2. 按文件扩展名加载对应语言文法（`tree-sitter-<lang>.so`）。
3. 解析文件得到 CST（具体语法树）。
4. 遍历 CST 节点，提取 class/method 定义及其行号区间。
5. 提取简单的调用关系（函数调用表达式 → 被调用函数名）。
6. 组装 IRDocument 返回。

### 5.3 注意事项

- 当前工作目录或配置路径需包含已编译的 `.so` 文法文件。
- 对无法识别的文件扩展名返回空 IR（非错误），由编排层跳过。
- 大文件（>10MB）解析超时处理：使用 context 控制。

## 6. SCIP 适配器实现指南

### 6.1 接口实现

实现 `BatchParser` 子接口：

```go
package adapter_scip

type SCIPAdapter struct {
    indexDir string
}

func (a *SCIPAdapter) Name() string { return "scip" }
func (a *SCIPAdapter) Parse(ctx context.Context, path string) (*parser.IRDocument, error) {
    // 从已加载的 index 中按文件路径查找
}
func (a *SCIPAdapter) ParseAll(ctx context.Context, paths []string) (<-chan *parser.IRDocument, error) {
    // 加载 SCIP index 文件，按文件分发 IR
}
```

### 6.2 关键步骤

1. 使用 `github.com/sourcegraph/scip/bindings/go/scip` 读取 index 文件。
2. 解析 `Document` 列表，提取每个文件的符号声明和引用关系。
3. 按文件路径分发到对应 IRDocument。
4. 提取精确的引用边（`Reference` 关系）。

### 6.3 输入要求

- SCIP index 文件由外部工具生成（`scip-java` / `scip-go` / `scip-clang` / `scip-typescript`）。
- 配置中指定 `scip.index_dir` 路径。

## 7. LSP 适配器实现指南（jdtls / clangd / gopls）

### 7.1 通用设计

```go
package adapter_lsp

type LSPAdapter struct {
    name    string
    cmd     string // LSP 子进程命令
    lang    string
    debounce time.Duration
}

func (a *LSPAdapter) Init(ctx context.Context, config map[string]any) error {
    // 启动 LSP 子进程
    // 发送 initialize 请求
    // 等待初始化完成
}

func (a *LSPAdapter) Parse(ctx context.Context, path string) (*parser.IRDocument, error) {
    // 发送 textDocument/documentSymbol 请求
    // 发送 textDocument/references 请求
    // 解析响应，组装 IRDocument
}
```

### 7.2 关键步骤

1. 启动 LSP 子进程（jdtls / clangd / gopls），通过 stdin/stdout 通信。
2. 发送 `initialize` 请求，等待 `initialized` 响应。
3. 打开文件：发送 `textDocument/didOpen` 通知。
4. 获取符号：发送 `textDocument/documentSymbol` 请求。
5. 获取引用：发送 `textDocument/references` 请求。
6. 关闭文件：发送 `textDocument/didClose` 通知。
7. 解析 JSON-RPC 响应，组装 IRDocument。

### 7.3 各 LSP 差异

| LSP | 启动命令 | 依赖 | 注意事项 |
|---|---|---|---|
| jdtls | `jdtls` | JDK 17+ | 需 `.classpath` 或 `pom.xml` / `build.gradle` |
| clangd | `clangd` | LLVM 工具链 | 需 `compile_commands.json` |
| gopls | `gopls` | Go 1.22+ | 需 `go.mod` 所在目录启动 |

## 8. 竞品直读适配器实现指南（CodeGraph / JCodeIndexer）

### 8.1 通用设计

```go
package adapter_codegraph

type CodeGraphAdapter struct {
    dbPath string
}

func (a *CodeGraphAdapter) Name() string { return "codegraph" }
func (a *CodeGraphAdapter) Supports(lang string) bool { /* 按语言返回 */ }

func (a *CodeGraphAdapter) ParseAll(ctx context.Context, paths []string) (<-chan *parser.IRDocument, error) {
    // 打开 CodeGraph SQLite 数据库
    // 读取 symbols 表和 edges 表
    // 按文件路径分发 IRDocument
}
```

### 8.2 关键步骤

1. 使用 `database/sql` + `go-sqlite3` 打开竞品 SQLite 数据库（只读）。
2. 查询 symbols 表：获取类、方法定义及其行号区间。
3. 查询 edges 表：获取调用关系。
4. 按文件路径分组，组装 IRDocument。
5. 如果数据库文件不存在或格式错误，返回 `ErrSourceUnavailable` 触发降级。

### 8.3 降级兜底

```go
func (a *CodeGraphAdapter) Parse(ctx context.Context, path string) (*parser.IRDocument, error) {
    if a.dbPath == "" || !fileExists(a.dbPath) {
        return nil, parser.ErrSourceUnavailable
    }
    // 正常解析逻辑
}
```

## 10. 开发指南

### 10.1 实现优先级

| 阶段 | 适配器 | 说明 |
|---|---|---|
| P0 | tree-sitter + CodeGraph 直读 | 通用兜底 + 竞品复用 |
| P1 | SCIP + jdtls + clangd + gopls + JCodeIndexer | 精确语义 + 多语言覆盖 |

### 10.2 实现步骤

1. **实现 tree-sitter 适配器**
   - 在 `internal/parser/adapter/treesitter/` 下创建包。
   - 实现 `ParserPlugin` 全部接口方法。
   - 单测：至少覆盖 3 种语言（Go / Java / TypeScript）的解析正确性。

2. **实现 CodeGraph 直读适配器**
   - 在 `internal/parser/adapter/codegraph/` 下创建包。
   - 实现 `BatchParser` 子接口。
   - 单测：使用测试用 CodeGraph SQLite 验证读取正确性。

3. **实现降级路径**
   - 在注册中心 `Select` 方法中实现优先级降级。
   - 单测：mock 源不可用，验证降级触发。

4. **实现 SCIP 适配器（P1）**
   - 在 `internal/parser/adapter/scip/` 下创建包。
   - 实现 `BatchParser` 子接口。

5. **实现 LSP 适配器（P1）**
   - 在 `internal/parser/adapter/lsp/` 下创建通用 LSP 框架。
   - 分别实现 jdtls / clangd / gopls 子包。

6. **实现 JCodeIndexer 直读适配器（P1）**
   - 在 `internal/parser/adapter/jcodeindexer/` 下创建包。
   - 实现 `BatchParser` 子接口。
