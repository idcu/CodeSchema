### 1.2 Embedding 模型

| 模型 | 适用场景 | 说明 |
|---|---|---|
| `bge-small-zh`（默认） | 多语言仓库（含中文） | BAAI 出品，平衡性能与质量，ONNX 版本（FP16 量化，512 维） |
| `bge-base-zh` | 多语言仓库（含中文） | 质量更高，资源消耗更大 |
| `text-embedding-3-small` | 英文仓库 | OpenAI 模型，需 API 调用 |
| `mxbai-embed-large` | 英文仓库 | 本地运行，无需外部 API |

> **ONNX 集成**：`bge-small-zh-v1.5` 已预转换为 ONNX 格式（FP16 量化），模型文件位于 `down/models/bge-small-zh-v1.5/`。`ONNXEmbedder` 自动检测模型文件，优先使用；若不可用则降级到 `LocalEmbedder`（TF-IDF 哈希）。
>
> **模型远程分发（E3 深化）**：模型缺失且配置了 `storage.vector.model_download_url` 时，启动自动下载并解包（`vector.ModelDownloader`）——
> 支持 `{model}` 占位符（替换 `embedding_model`）、可选 SHA-256 校验（`model_sha256`）、幂等（已存在跳过）、
> **分发源类型**：`model_download_url` 支持 `https://`（远程下载）、`file://`（本地文件直读，无网络环境可用 `make models-pack` 产物）与本地路径三种；
> **本地产物零配置分发**：`make models-pack MODEL=<name>` 产物（`build/models-<name>.tar.gz`）存在时，`Ensure` 自动回填 `file://` 本地源（无需配置 URL）——支持带顶层目录的归档布局（自动剥离）并跳过 macOS `._*` 元数据条目；
> **本地优先零下载**：`Ensure` 先检查 `down/models/<embedding_model>/` 是否已含 `onnx/*.onnx` + `tokenizer.json`——仓库内模型已就位时直接命中、**完全不触发下载**（URL 为空、注册表未命中均不影响）；`TestRealModelDirPresent` 用真实模型目录守护该路径。
> **本地端到端已验证（x86_64 mac）**：`down/models/bge-small-zh-v1.5/`（真实模型）+ `down/onnxruntime/libonnxruntime.dylib`（x86_64 库）→ `-tags onnx` 构建下 `NewONNXEmbedderOrFallback` 完成**真实嵌入推理**（dim=512，`TestLocalONNXEmbedE2E`）；平台库选择已修复——按 `runtime.GOOS` 选 `onnxruntime.dll`/`libonnxruntime.so`/`libonnxruntime.dylib`（不再误载 Windows dll）；本机 ORT 1.23.2 仅支持 API v1..23，绑定经 `third_party/onnxruntime_go_patch`（`ORT_API_VERSION 28→23`）适配。
> **内置模型注册表**（`vector.ModelRegistry`，含 bge-small-zh/bge-base-zh）：未配置 URL 时按 `embedding_model` 自动查表回填下载地址（无需手填），未知模型仍走显式配置；
> 解包防路径穿越；下载/校验失败优雅降级到 LocalEmbedder。环境变量：`CODESCHEMA_STORAGE_VECTOR_MODEL_DIR` /
> `CODESCHEMA_STORAGE_VECTOR_MODEL_DOWNLOAD_URL` / `CODESCHEMA_STORAGE_VECTOR_MODEL_SHA256`。

## 2. 索引构建流程

### 2.1 异步 Embedding

```
入库成功 → 异步队列 → 对 doc_comment/方法签名/类摘要做 embedding
            → 写入向量库（chromem-go）
            → AI 补全 doc 后同步触发重建
```

- 入库成功后异步对 `doc_comment`、方法签名、类摘要做 embedding 写入向量库。
- AI 生成的 doc 补全同步触发重建。
- 使用 worker pool 控制并发 embedding 请求数。

### 2.2 索引构建接口

```go
// internal/vector/indexer.go
package vector

type Indexer struct {
```

## 3. 检索流程

### 3.1 双路检索架构

```
用户查询 (q)
    │
    ├──→ FTS5 精确搜索（符号名、签名、doc_comment）
    │       │
    │       └──→ 结果集 A（精确匹配，高权重）
    │
    └──→ 向量语义搜索（Top-K）
            │
            └──→ 结果集 B（语义相似，权重调节）
                    │
                    └──→ 融合重排 → 最终结果
```

### 3.2 FTS5 全文搜索

使用 SQLite FTS5 对全限定名、方法签名、doc_comment 建立全文索引。

```sql
-- FTS5 虚拟表定义
CREATE VIRTUAL TABLE symbol_fts USING fts5(
    full_name,
    signature,
    doc_comment,
    content='',              -- 空 content，由应用层维护
    tokenize='unicode61'
);

-- 查询示例（前缀匹配 + 模糊匹配）
SELECT full_name, rank FROM symbol_fts
WHERE symbol_fts MATCH 'order* OR payment*'
ORDER BY rank;
```

**支持特性**：
- 前缀匹配（`order*`）
- 模糊匹配（`~` 运算符）
- 布尔查询（`AND`/`OR`/`NOT`）
- 短语查询（`"create order"`）

### 3.3 向量检索

```go
// Search 语义搜索，返回 Top-K 结果。
func (idx *Indexer) Search(ctx context.Context, q string, k int) ([]Result, error) {
    vec, err := idx.model.Embed(ctx, q)
    if err != nil {
        return nil, err
    }
    return idx.db.Search(ctx, vec, k)
}
```

## 5. 开发指南

### 5.1 实现步骤

1. **集成 chromem-go**：在 `go.mod` 中添加 `chromem-go` 依赖，实现 `internal/vector/store.go` 初始化向量库连接。
2. **实现 Embedding 构建**：在 `internal/vector/indexer.go` 中实现异步 embedding 构建逻辑，支持模型切换。
3. **实现 FTS5 全文搜索**：在 `internal/store/schema.go` 中追加 FTS5 虚拟表 DDL，实现 `internal/search/fts.go` 查询逻辑。
4. **实现双路检索**：在 `internal/search/searcher.go` 中整合 FTS5 精确搜索与向量语义搜索。
5. **实现融合重排**：在 `internal/search/reranker.go` 中实现融合得分计算与去重排序。
6. **单元测试**：使用 chromem-go 嵌入式实例测试向量检索，使用内存 SQLite FTS5 测试全文搜索，测试融合重排正确性。
