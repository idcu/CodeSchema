# CodeSchema 仓库结构总览

> 写给：想快速搞清楚「根目录里每个文件夹/文件是干嘛的、要不要进版本库」的人（新人 / 开发者 / 运维通用）。
> 核心原则：Go 惯用目录（`cmd` / `internal` / `vendor`）不动；源码与配置进版本库；构建产物、下载缓存、运行期数据、临时草稿一律 gitignore，不污染仓库。

## 根目录逐项说明

| 路径 | 类型 | 是否进版本库 | 功能 / 用途 |
|---|---|---|---|
| `cmd/` | 目录（Go 惯用） | ✅ | 主程序入口 `cmd/codeschema`，分发 `scan` / `watch` / `serve` / `mcp` / `benchmark` / `agent-bench` / `version` 子命令。**不可改名**（Go 惯用约定）。 |
| `internal/` | 目录（Go 惯用） | ✅ | 全部内部业务包（`analyzer` / `parser` / `store` / `server` / `vector` / `ai` / `runtime` 等），不对外暴露。**不可改名**。 |
| `vendor/` | 目录（Go 惯用） | ❌（gitignore） | 依赖 vendoring。`go mod vendor` 生成。**不可改名**。 |
| `go.mod` / `go.sum` | 文件 | ✅ | Go 模块定义与依赖锁。 |
| `config.yaml.example` | 文件 | ✅ | 配置样例（监听地址、存储后端、auth_token、向量模型等）；部署时复制为 `config.yaml`。 |
| `Makefile` | 文件 | ✅ | 构建 / 测试 / 交叉编译 / 计数守护 / 模型打包等任务入口（`make build` / `test` / `cross` / `counts-check` / `models-pack` …）。 |
| `README.md` | 文件 | ✅ | 项目总入口 README。 |
| `AGENTS.md` | 文件 | ✅ | AI 编程工具（Agent）接入指南。 |
| `DEV_PROGRESS.md` | 文件 | ✅ | 开发进度（P0 骨架 ~ P18，开发里程碑轴）。 |
| `CHANGELOG.internal.md` | 文件 | ✅ | 内部变更日志（历史留痕，保留不改）。 |
| `docs/` | 目录 | ✅ | 按人群分层文档：`00-新人上手` / `01-开发者` / `02-架构师` / `03-部署运维` / `04-贡献者` + `AI协作规范.md` + 本文件。文档均以源码事实为基线。 |
| `scripts/` | 目录 | ✅ | 构建 / CI 辅助脚本：计数审计（`project_counts.py` / `counts_check.py`）、基准趋势（`benchtrend`）、快速起步（`quick-start.*`）、发布检查（`check-*.sh`）、MCP 探针（`mcp_probe.py`）。 |
| `contrib/` | 目录 | ✅ | 社区 / 示例贡献：`adapterx`（适配器扩展）、`contextsdk`（上下文 SDK）、`dsh`（调试 shell）。 |
| `third_party/` | 目录 | ✅ | 第三方补丁 / 资源（如 `onnxruntime_go_patch`）。 |
| `docker/` | 目录 | ✅ | Docker 相关脚本（如 `lsp-test` 镜像构建）。 |
| `Dockerfile` | 文件 | ✅ | 主服务镜像构建。 |
| `Dockerfile.mirror` | 文件 | ✅ | 镜像源加速构建变体。 |
| `docker-compose.yml` | 文件 | ✅ | 本服务容器编排。 |
| `docker-compose.idcu-go.yml` | 文件 | ✅ | 与 idcu-go 兄弟模块联调编排。 |
| `build/` | 目录 | ❌（gitignore 部分） | **构建产物输出目录**：编译二进制（`build/codeschema`）、覆盖率、基准 JSON/HTML、多租户 demo 产物。`make build` / `make cross` 输出到此。 |
| `down/` | 目录 | ⚠️ 部分（归档/模型 gitignore，chromem-go 源码与 onnxruntime 库进库） | **第三方下载缓存**：ONNX runtime 原生库、tree-sitter CLI、chromem-go 源码、bge 等嵌入模型。运行期 `internal/runtime` 默认从此目录解析模型与 onnxruntime 库；`make models-pack` 从此打包模型。 |
| `data/` | 目录 | ❌（gitignore） | **运行期数据**：FTS / IDF 索引、向量数据、`store.lock` 等。 |
| `analysis/` | 目录 | ❌（gitignore） | **临时分析草稿**：竞品分析、评审草稿等，不纳入版本库。 |
| `codeschema` / `codeschema-onnx` | 文件 | ❌（gitignore） | **手动构建产物**（Mach-O 可执行）：由 `go build`（默认）/`go build -tags onnx` 直接产出到根目录。建议改用 `make build` / `make build-onnx` 产出到 `build/`，保持根目录干净。 |
| `.github/` | 目录 | ✅ | CI/CD 工作流（`ci.yml` / `release.yml`）。 |
| `.gitignore` / `.dockerignore` | 文件 | ✅ | 忽略规则。 |
| `.workbuddy/` | 目录 | ❌（本地） | 本地 agent 工作记忆，不提交。 |
| `.DS_Store` | 文件 | ❌（应 gitignore） | macOS 目录元数据垃圾，已加入 `.gitignore`。 |

## 命名与位置建议（已落地 / 待定）

- **构建二进制 → `build/`（已落地）**：新增 `make build-onnx`（输出 `-tags onnx` 变体到 `build/codeschema-onnx`）。根目录的 `codeschema` / `codeschema-onnx` 为手动 `go build` 副产物（已 gitignore），建议统一用 `make build` / `make build-onnx` 产出，避免散落根目录。
- **`down/` 命名（待定）**：该目录承载第三方下载缓存，名称 `down` 语义不明。候选：`downloads/`（更直白）或更精确表述。但因 `internal/runtime/runtime.go` 等运行期代码硬编码了 `down/models` 与 `down/onnxruntime` 路径，改名属需评审的破坏性变更，是否执行见仓库根决策（询问 owner）。
- **Go 惯用目录不动**：`cmd` / `internal` / `vendor` 为 Go 语言约定，改名会破坏 import 路径，维持现状。

## 一句话导航

- 想读文档 → `docs/README.md`（按人群地图）
- 想构建运行 → `make build`（默认）/ `make build-onnx`（语义嵌入）/ `make test`
- 想改文档同步 → `docs/AI协作规范.md` §4
- 想查计数口径 → `make counts` / `make counts-check`
