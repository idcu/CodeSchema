# CodeSchema 仓库结构总览

> 写给：想快速搞清楚「根目录里每个文件夹/文件是干嘛的、要不要进版本库」的人（新人 / 开发者 / 运维通用）。
> 核心原则：Go 惯用目录（`cmd` / `internal` / `vendor`）不动；源码与配置进版本库；构建产物、下载缓存、运行期数据、临时草稿一律 gitignore，不污染仓库。

> 最后更新：2026-09-02

## 根目录逐项说明

## 各目录子项清单

> 对上表逐项「下钻」，列出关键子目录 / 文件 / 子命令，便于定位与导航。所有条目均按 `ls` 与源码实地核查（`cmd/codeschema/main.go` 子命令分发、`internal/` 顶层目录枚举）得出，未做臆测。

### cmd/codeschema/ — 子命令（8 个）

| 子命令 | 作用 |
|---|---|
| `scan <path>` | 全量扫描仓库并入库（解析 → 索引 → IDF → 标签推导） |
| `watch <path>` | 文件监听增量（默认轮询，`--fsnotify` 切原生监听） |
| `rebuild-kv` | 重建 KV 缓存（P2） |
| `benchmark` | 全链路基准（扫描 / 索引 / 检索指标，多仓库对比） |
| `agent-bench` | Agent 端到端基准（实现于 switch，但未在 `-h` 用法里列出） |
| `mcp` | 启动 MCP Server（SSE，可选 `--stdio` 直连） |
| `serve` | 启动 HTTP API Server（可选同进程起 MCP） |
| `version` | 显示版本信息 |

> 注：存储后端接线（sqlite / pg / redis）在 `store_dispatch.go` 经 build-tag 分发；因 pg/redis 子包反向依赖 `internal/store`（实现其接口），分发须落在 cmd 层以避免循环依赖。

### internal/ — 顶层包目录（26 个；含嵌套子包共 32 个 internal Go 包，以 `make counts` 为准）

- `scanner` — 仓库扫描调度
- `parser` — 解析适配器注册中心（tree-sitter 兜底 + LSP / SCIP / CodeGraph 高精度优先）
- `store` — 存储后端接口 + file / sqlite 实现（pg / redis 经 build-tag 接线）
- `server` — MCP / HTTP 服务 + 向量索引可视化 `/viz`
- `service` — 业务编排（BuildIndex / RunTagAll）
- `runtime` — 运行期组件装配（NewSearcher / NewParserRegistry / WithImpactAnalyzer / RunTagAll）
- `tenant` — 多租户管理（单进程服务多个隔离仓库）
- `config` — 配置加载、环境变量覆盖、热重载
- `search` — FTS 双路检索 / rerank
- `vector` — 向量存储与索引
- `embedding` — 文本嵌入管线
- `retrieval` — 召回 / 检索抽象
- `analyzer` — 影响面 / 依赖分析
- `scheduler` — 增量调度（debounce 队列）
- `watcher` — 轮询 / fsnotify 监听实现
- `fswatch` — 文件监听（fsnotify 封装）
- `ai` — AI 增强（标签 / 上下文增强）
- `benchmark` — 全链路基准框架
- `scalebench` — 规模基准（多量级 sqlite）
- `adapterbench` — 解析适配器基准对比
- `agentbench` — Agent 端到端基准
- `integration` — 集成测试辅助
- `testutil` — 测试工具
- `errors` — 统一错误类型
- `hash` — 哈希工具
- `lock` — 分布式 / 文件锁

## 命名与位置建议（已落地 / 待定）

- **构建二进制 → `build/`（已落地）**：新增 `make build-onnx`（输出 `-tags onnx` 变体到 `build/codeschema-onnx`）。根目录的 `codeschema` / `codeschema-onnx` 为手动 `go build` 副产物（已 gitignore），建议统一用 `make build` / `make build-onnx` 产出，避免散落根目录。
- **`down/` 命名（保持现状）**：该目录承载第三方下载缓存，名称 `down` 语义虽不够直白，但因 `internal/runtime/runtime.go:181/183` 运行期代码硬编码了 `down/models` 与 `down/onnxruntime` 路径，改名属评审级破坏性变更。经 owner 评审决策：**保持 `down/` 不动**，用途已在本表说明。
- **Go 惯用目录不动**：`cmd` / `internal` / `vendor` 为 Go 语言约定，改名会破坏 import 路径，维持现状。
