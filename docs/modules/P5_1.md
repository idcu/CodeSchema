# P5_1 全文检索与融合重排

> 模块编号：P5_1 ｜ 父模块：P5 检索层 ｜ 完成度：100% ｜ 代码：`internal/search`（searcher.go / builder.go / fts.go / fts_persistent.go / reranker.go / adapter.go）

## 🎯 模块用途

检索层实现本身。FTS 引擎负责精确召回（符号名/签名），向量适配器负责语义召回（委托 P6），融合重排合并两路结果。IndexBuilder 负责索引的构建/增量维护/IDF 词典持久化，与 Searcher 读写分离。

## 🧱 拆分逻辑说明

按**职责边界（读/写分离）**在包内组织：Searcher（读）与 IndexBuilder（写）分离，FTS 引擎分 Memory/Persistent 两实现（Persistent 落盘 json 防重启丢失），VectorAdapter 把 P6 能力适配进统一 Searcher 接口。

## ⚙️ 技术说明

**技术选型**：自研倒排索引；IDF 词典（json 文件持久化）；向量适配委托 P6（`search.NewVectorAdapter(indexer)`）。

**对外接口契约**：
- `FTSEngine` 接口：`Add`/`Search`/`Delete`/`Save`/`Load`（MemoryFTS + PersistentFTS 两实现）
- `Searcher.Search(ctx, query, mode, limit)` — exact/both
- `IndexBuilder`：`BuildAndIndex(ctx, st, filePath)` / `BuildAndRemove(ctx, st, filePath)` / `StartAsync(ctx, queue, workers)` / `SaveIDF` / `AutoSaveIDF`
- `NewSearcher(fts, vectorAdapter, reranker)` — 组合装配

**依赖的下层模块**：P6_1 向量索引（Indexer 封装）、P6_2 嵌入器（Embedder）、P7 存储层（读记录构建索引）、P8_2 日志。

**数据模型**：倒排索引（term→doc 列表）、IDF 词典（term→权重，json 持久化）、`BuildResult{IndexedDocs, Duration}`。

## 🔄 替代方案

- 接外部搜索服务：见 P5 替代方案，不重复。
- FTS 只用内存实现：重启丢索引需全量重建；Persistent 落盘是生产必要（当前已实现）。
