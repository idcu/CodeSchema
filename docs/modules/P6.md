# P6 向量索引层（Vector Index Layer）

> 模块编号：P6 ｜ 父模块：无（一级） ｜ 完成度：96%（索引核心 97%，嵌入器 95%，模型分发 97%）

## 🎯 模块用途

语义检索的**基础设施层**：把文本/符号嵌入为向量（Embedder），存入向量存储（VectorStore），并提供索引（Indexer）与检索接口。是「向量语义检索」「/viz 可视化」「语义模型远程分发」三块能力的底座。

## 🧱 拆分逻辑说明

按**技术分层（语义检索基础设施）+ 变更频率**划分：

- P6_1 索引核心（VectorStore + Indexer + 持久化）：定义向量存储抽象，变更最保守。
- P6_2 嵌入器（Local/ONNX）：算法与推理路径，变更频率最高（模型升级、嵌入维度调整）。
- P6_3 模型分发（下载 + 校验 + 注册表）：模型文件生命周期管理，与运行时逻辑独立。

边界：索引核心只认识向量，不认识文本语义；嵌入器只负责「文本→向量」；模型分发只负责「模型文件就位」。三者可独立替换升级。

## ⚙️ 技术说明

**技术选型**：`chromem-go`（fork 于 `down/chromem-go/`，`replace` 本地化）；ONNX 推理（`onnxruntime_go`，本地 patch 于 `third_party/`，`-tags onnx` 可选）；自研 LocalEmbedder（TF-IDF + dim 512）。

**对外接口契约**：`VectorStore` 接口（`Add`/`BatchAdd`/`Search`/`Delete`/`Size`/`ListIDs`）+ `Embedder` 接口（`Embed`/`Dim`）（见子模块）。

**依赖的下层模块**：P8_2 日志。
**被依赖方**：P5_1 检索（Indexer/Searcher）、P1_3 HTTP（/viz）、P1_1 CLI（向量栈装配）。

**数据模型**：向量存储（id→vector）；持久化 json 文件。

## 🔄 替代方案

- 外部向量数据库（Milvus/Qdrant/pgvector）：亿级场景更强，但引入部署服务；当前单机持久化向量存储满足规模，PG 后端预留了 pgvector 演进路径（见 P7_3）。
- 只用 FTS 不做向量：语义召回缺失，不满足双路检索目标。

## 📊 完成度：96%

已做：VectorStore 三实现（Memory/Persistent/Chromem）、Indexer、Local + ONNX 双嵌入器、**语义质量定案**（ONNX R@1=1.00 vs Local 0.42）、模型公网分发闭环（注册表 URL 回填 + 真实制品端到端）、**模型下载断点续传**（Range 续传 + .part 复用）、向量原文持久化（DocContentStore，/viz 展示原文）、/viz 复用同一索引。
未做：ONNX 多仓库 recall 持续对比基准（质量看护可并入 CI）。

## 🚧 阻塞与风险

- ONNX 嵌入器依赖 gcc + onnxruntime 动态库（非默认构建路径，`-tags onnx`）。
- 模型文件缺失自动降级 LocalEmbedder——语义质量差异需文档化。
- 第三方依赖本地化（chromem-go/onnxruntime_go patch），上游升级需重新验证。
