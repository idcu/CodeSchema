# P2_1 服务编排 Service

> 模块编号：P2_1 ｜ 父模块：P2 编排层 ｜ 完成度：100% ｜ 代码：`internal/service`（service.go / testlink.go / coverprofile.go）

## 🎯 模块用途

接入层的唯一查询入口与写路径收口点。把解析（IR）、检索（FTS+向量）、分析（影响面/标签）、存储（Store）四类原始能力组合为业务语义方法：符号搜索、上下文裁剪、影响面分析、关联测试、标签体系、覆盖率对接。同时负责索引构建编排（全量/增量/异步队列/IDF 持久化）。

## 🧱 拆分逻辑说明

按**职责边界（查询聚合器）**独立：接入层（P1）三个协议面都需要同一套查询语义，若各自实现会重复且易漂移。Service 是「依赖注入的中枢」——通过 `WithSearcher`/`WithIndexBuilder`/`WithImpactAnalyzer`/`WithAIEnhancer` 组装可选能力，未注入组件时优雅降级（如无 AI 增强时禁用同名消歧）。

与 Scanner 的边界：Scanner 管「解析入库」，Service 管「索引构建与查询聚合」。

## ⚙️ 技术说明

**技术选型**：Go 标准库；组件可选项（nil 安全）注入模式。

**对外接口契约（核心方法）**：

| 方法 | 说明 |
|---|---|
| `Search(ctx, query, mode, limit)` | 双路检索（exact/both） |
| `GetContext(ctx, symbol, contextLines)` | 符号上下文裁剪 |
| `GetImpact(ctx, method, depth)` | 影响面分析（callers/callees） |
| `GetTests(ctx, method, minConfidence)` | 关联单测 |
| `GetAffected(ctx, symbol, recursive)` | 受影响符号列表 |
| `FindDependencies` / `GetCallGraph` | 依赖与调用图 |
| `GetTags` / `SearchByTag` / `GetAllTags` | 标签体系 |
| `BuildIndex(ctx)` | 全量索引构建（FTS + 向量 + IDF） |
| `LoadGoCoverProfile` / `ParseGoCoverProfile` | Go coverprofile 解析接入 |
| `Health` | 健康状态 |

**依赖的下层模块**：P3_1 解析核心（IR 结构消费）、P4_1 Analyzer（影响面）、P4_2 AI（同名消歧/标签补全）、P5_1 检索（Searcher + IndexBuilder）、P7 存储层（Store）。

**数据模型**：`SymbolContext`/`ImpactResult`/`TestResult`/`TagResult` 等查询结果结构；`TestLink`（测试关联，支持 coverprofile 行号映射）。

## 🔄 替代方案

- Service 与接入层合并：三个协议面各自调用 Analyzer/Search/Store → 重复实现、接口漂移，不可取。
- 引入 DI 容器（wire/fx）：当前 5 个 `With*` 注入已足够清晰，wire 的代码生成对单服务无收益。
