# P9_4 集成测试

> 模块编号：P9_4 ｜ 父模块：P9 测试与基准 ｜ 完成度：95% ｜ 代码：`internal/integration`（integration_test.go / multirepo_test.go / realrepo_test.go）

## 🎯 模块用途

提供**端到端集成测试**：用真实仓库 fixture 走通「扫描 → 解析 → 入库 → 建索引 → 检索」全链路，验证各模块协同正确性。是「单元测试各自绿、合起来挂」的最后防线。

## 🧱 拆分逻辑说明

按**职责边界（链路协同验证）**独立：集成测试横跨 parser/scanner/search/store/vector，依赖面最广，独立成包避免污染被测包；`benchhelper.go`/`benchreport.go` 提供集成场景下的基准辅助工具。

## ⚙️ 技术说明

**技术选型**：Go `testing` + 真实 fixture 仓库；`encoding/json` 报告。

**对外接口契约**：端到端测试函数集 + 集成基准辅助函数。

**依赖的下层模块**：P2_2 Scanner、P3 解析层、P5_1 检索、P6 向量、P7 存储层。

**数据模型**：无自有模型（消费各层 IR/记录/索引结果）。

## 🔄 替代方案

- 只用单元测试：层间契约漂移发现不了；集成测试是必须的最后一环。

## 📊 完成度：95%

已做：真实 fixture 全链路集成测试（`TestFullPipeline_*`：扫描→入库→建索引→检索 + 去重扫描 + 索引一致性 + 结果富化）、**多仓库对比**（`TestMultiRepo_CollectMetrics`）、**真实仓库**（`TestRealRepo_CollectMetrics`）、集成场景基准辅助（benchhelper/benchreport）。
未做：更多真实仓库（多语言混合仓库）场景扩充（持续演进项）。

## 🚧 阻塞与风险

- 无阻塞。集成测试运行时长随 fixture 规模增长，需控制用例规模保证 CI 时长。
