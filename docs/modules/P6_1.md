# P6_1 向量索引核心

> 模块编号：P6_1 ｜ 父模块：P6 向量索引层 ｜ 完成度：95% ｜ 代码：`internal/vector`（store.go / chromem.go / persistent.go / indexer.go / model.go）

## 🎯 模块用途

定义向量存储抽象并提供三种实现 + 索引器。解决「向量存哪里、怎么建索引、怎么检索」的问题：

- `VectorStore` 接口：Memory（内存）、Persistent（json 落盘）、Chromem（chromem-go 向量库）三实现，运行时可插拔。
- `Indexer`：把 Embedder 与 VectorStore 组合，对外提供文档级索引/检索能力。

## 🧱 拆分逻辑说明

按**技术分层（存储抽象）**独立：与嵌入器（算法）和模型分发（文件管理）解耦——嵌入器换算法不影响存储结构；存储后端换实现不影响上层 Searcher。`DocContentStore` 可选接口让 Persistent/Memory 支持文档原文，供 /viz 浏览。

## ⚙️ 技术说明

**技术选型**：`chromem-go`（`replace` 到 `down/chromem-go/`）；自研持久化（json + 原子写）。

**对外接口契约**：
- `VectorStore`：`Add(ctx,id,vector)` / `BatchAdd` / `Search(ctx,query,k)` / `Delete` / `Size` / `ListIDs` / `Close`
- `NewMemoryStore()` / `NewPersistentStore(file)` / `NewChromemStore(...)`
- `Indexer`：`Add`/`Search`/`Delete` 文档级接口
- 工厂：`vector.NewIndexer(store, em, workers)`

**依赖的下层模块**：P6_2 嵌入器（Embedder 接口）、P8_2 日志。

**数据模型**：id→向量 映射；`SearchResult{ID, Score}`；持久化为 json 文件。

## 🔄 替代方案

- 只用 chromem-go 单一实现：其文档内容支持有限，Persistent/Memory 作为默认栈保证 /viz 与检索一致性，三实现并存是刻意的冗余设计。
- 接外部向量库：见 P6 替代方案。
