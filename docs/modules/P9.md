# P9 测试与基准（Test & Bench）

> 模块编号：P9 ｜ 父模块：无（一级） ｜ 完成度：96%（benchmark 100%，其余 95~97%）

## 🎯 模块用途

承载系统的**验证与压测体系**：全链路基准（扫描/索引/检索指标 + 多仓库对比）、超大仓性能基准（BulkUpsert 回归看护）、适配器验证基准（AST gate 对比）、端到端集成测试。解决「系统性能与质量不可度量、回归不可发现」的问题。

## 🧱 拆分逻辑说明

按**职责边界（验证场景）**划分，四个子模块各盯一类验证：

- P9_1 Benchmark：全链路（扫描/索引/检索）性能基准，多仓库横向对比。
- P9_2 ScaleBench：超大仓写入基准，固化进 CI 看护 `BulkUpsert` 回归（`BenchmarkScaleBulk` N=1万）。
- P9_3 AdapterBench：解析适配器精度对比（正则 vs AST gate vs treesitter），输出 `build/adapter-bench.json`。
- P9_4 Integration：端到端集成测试（真实仓库 fixture 全链路）。

边界：全部是**独立轻量包**，仅依赖被测目标，不引入 onnxruntime 等重型依赖（保证秒级编译运行）。

## ⚙️ 技术说明

**技术选型**：Go `testing` + `testing.B` 基准框架；CI 固化（`.github/workflows/ci.yml` bench job）。

**对外接口契约**：基准输出文件（`build/*.json`）+ 分析报告（`analysis/*.md`）。

**依赖的下层模块**：P2_2 Scanner、P3 解析层、P5_1 检索、P7 存储层、P6 向量层、P8。

**数据模型**：基准结果 JSON Schema（指标：耗时/吞吐/精度）。

## 🔄 替代方案

- 外部压测工具（wrk/vegeta）：只覆盖 HTTP 层，覆盖不到包级基准；Go testing.B 与包级基准是正解。
- 不设基准体系：性能回归无法发现（BulkUpsert 500 倍退化就是教训），CI 固化是必须的。
