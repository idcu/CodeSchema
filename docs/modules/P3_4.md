# P3_4 LSP 适配器

> 模块编号：P3_4 ｜ 父模块：P3 解析层 ｜ 完成度：90% ｜ 代码：`internal/parser/adapter/lsp`

## 🎯 模块用途

通过启动**真实语言服务器**（LSP 协议，如 Go 的 gopls、C++ 的 clangd）提取最高精度的符号与调用关系。语言服务器拥有编译级语义信息，精度远超静态解析，是「高质量语义提取」的终极手段。

## 🧱 拆分逻辑说明

按**数据来源（运行时语言服务）**独立：LSP 是进程型外部服务，需要 JSON-RPC 传输层、进程生命周期管理、超时/取消处理——这些基础设施与纯解析逻辑完全不同，独立成模块隔离复杂度。

## ⚙️ 技术说明

**技术选型**：手写 LSP JSON-RPC 客户端（bufio 读写、多行头解析）；`os/exec` 启动语言服务器进程；`internal/robust` 超时/恢复。

**对外接口契约**：实现 `parser.ParserPlugin`；`NewLSPServer` 管理语言服务器进程生命周期；SymbolKind 映射（修复过 Go Struct(23)/Interface(24)/Function(12) 漏映射的**生产缺陷**）。

**依赖的下层模块**：P3_1 解析核心、P8_5 错误体系、P8_2 日志、P8_3 指标、P8_6 健壮性。

**数据模型**：LSP `textDocument/documentSymbol` 响应 → `parser.IRDocument`。

## 🔄 替代方案

- 直接调 gopls/clangd CLI 一次性输出：无法复用进程、延迟高；长驻进程复用更优。
- 只用静态解析：对大项目精度不足，LSP 是精度兜底的关键路径。
