# P7_3 PostgreSQL 驱动

> 模块编号：P7_3 ｜ 父模块：P7 存储层 ｜ 完成度：85% ｜ 代码：`internal/store/pg`（pg.go 564 行）

## 🎯 模块用途

提供 **PostgreSQL 权威存储**，面向亿级横向扩展场景。`storage.driver=pg|postgres` + `storage.dsn=postgres://...` 启用（需 `-tags pg` 构建）。为「大规模部署 + 未来 pgvector 语义向量」预留路径。

## 🧱 拆分逻辑说明

按**部署单元（独立驱动积木）**独立：PG 是重型外部服务驱动，与 file/sqlite 的零依赖定位完全不同。`//go:build pg` 隔离使其**默认构建不含**，不污染免 CGO 默认构建。分发经 cmd 层 build-tag 接线（防循环依赖约束）。

## ⚙️ 技术说明

**技术选型**：`github.com/lib/pq`（驱动）+ `database/sql`；`-tags pg` 条件编译。

**对外接口契约**：实现 `store.Store` 全部方法（含 `UpsertIR`/`BulkUpsert`）。

**依赖的下层模块**：P3_1（IR）、P7_1（Store 接口）、`lib/pq`。
**外部服务**：PostgreSQL 实例（连接串 `storage.dsn`）。

**数据模型**：与 SQLite 同构的 DDL（file/class/method/call/tag 表），可按需扩展分区/索引。

## 🔄 替代方案

- SQLite 单机扩容：单文件存储无法水平扩展，亿级场景必须 PG。
- 云数据库（TDSQL/云上 PG）：部署托管化，连接串配置即可，本驱动天然兼容。

## 🚧 阻塞与风险

- 嵌入式 PG 首启需下载 PG 二进制（~40MB，缓存于 `~/.embedded-postgres-go/`），离线环境需预置；外部实例 / 本机 localhost 优先。
