# P5 检索层（Search Layer）

> 模块编号：P5 ｜ 父模块：无（一级） ｜ 完成度：100%

## 🎯 模块用途

提供**双路检索 + 融合重排**能力：FTS 全文精确检索（符号名/签名匹配）+ 向量语义检索（embedding 相似度），两者结果经重排器融合排序。支撑 `search_symbols`/`context` 等查询的召回质量，解决「关键词记不准也能搜到」的问题。

## 🧱 拆分逻辑说明

按**业务域（查询检索）**划分：检索层是只读消费方，消费 Store 的 IR 记录与 Vector 的向量索引，不生产数据。与写入链路（Scanner/Store）彻底分离——索引由 Service 的 IndexBuilder 构建，检索由 Searcher 消费，构建/检索分离保证「写时不阻塞读」。

P5 只有 P5_1 一个子模块（内部再分 FTS 引擎、IndexBuilder、Searcher、Reranker），因为 `internal/search` 是一个内聚包。

## ⚙️ 技术说明

**技术选型**：自研 FTS（倒排索引 + IDF 词典，Memory/Persistent 双实现）；向量侧委托 P6；融合重排（score 归一化合并）。

**对外接口契约**：
- `Searcher.Search(ctx, query, mode, limit)` — mode: exact(仅 FTS) / both(双路融合)
- `IndexBuilder.BuildAndIndex/BuildAndRemove` — 增量索引维护
- `IndexBuilder.SaveIDF/AutoSaveIDF/StartAsync` — IDF 词典持久化与异步队列

**依赖的下层模块**：P3_1（IR）、P6 向量索引层、P7 存储层（读记录）、P8 公共模块。

**数据模型**：FTS 倒排索引 + IDF 词典（json 持久化）；向量索引委托 P6。

## 🔄 替代方案

- 外部搜索引擎（Elasticsearch/Meilisearch）：功能强但引入部署依赖，自研 FTS 对单机 KV 场景足够且零依赖。
- 只做 FTS 不做向量：关键词记不准时召回差；双路融合是 P8 明确诉求，保留。
