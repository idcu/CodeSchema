## 一句话定位

**CodeSchema** 是一个面向 AI 辅助开发的高性能**代码元数据索引与上下文裁剪服务**：自动扫描代码仓库，建立类/方法/接口/调用关系的结构化索引，并配合同步检索，为 AI 编程工具（Trae / Cursor / Copilot / Claude Code 等）供给**精准裁剪后的代码上下文**，让 AI 生成更准、更省 token、更能理解改动的连锁影响。

## 核心能力

| 能力 | 说明 |
|---|---|
| 代码理解 | 类/方法/参数/继承/调用关系/标签，多语言（Go/Java/Python/TS/Rust/C++ 等 30 种） |
| 上下文裁剪 | 精准抽取 AI 所需的上下文，避免整篇喂入，显著降低 token 成本 |
| 影响面分析 | 改一个方法，反查所有受影响调用方与关联单测 |
| 双路检索 | 精确全文检索 + 语义检索（ONNX 向量），语义敏感场景 Recall@1=1.00（bge-small-zh-v1.5） |
| 开箱即用 | 三层存储（file/SQLite/PG + Redis + 向量/全文），免 CGO 纯 Go 构建 |
| 安全可控 | 本地数据存储、可选认证、不存源码原文（仅结构元数据） |

## 价值

- **给开发者/团队**：AI 生成代码更贴合真实仓储，减少返工；测前反查影响面。
- **给管理者**：少花在"AI 乱猜符号、重复问上下文"上的成本；token 开销更可预测。
- **给甲方**：本地/私有化部署，数据不出内网；能力经真实基准验证（31 个 Go 包测试全绿、10 万+ 文件压测、ONNX 语义检索召回 1.00）。

## 规模与可信度

- 单实例多租户，一个进程服务多个隔离仓库。
- 线性扩展：4x 文件 → ~1.6x 扫描 / ~1.9x P95 延迟。
- 部署形态：CLI 扫描 + MCP Server（SSE/stdio）+ HTTP API；Docker Compose 一键。
