# 测试指南

> 写给谁：测试、开发者、AI 编程工具、CI 维护者
> 写什么：测试命令、环境、核心场景、覆盖要求、基准回归
> 核心原则：命令复制即跑；改动必跑对应测试与基准；测试数据须真实
> 优先级：P2
> 最后更新：2026-08-17

---

## 1. 快速开始

```bash
go build ./... && go vet ./... && go test ./... -count=1   # 完整自检
make test                 # go test ./...
make test-race            # -race 竞态检测
make test-cover           # 覆盖率
make lint                 # go vet
```

## 2. 环境与约束

- Go 1.25+；默认免 CGO（不装 gcc 也能跑）。
- `-tags onnx` / `-tags pg,redis` 分支测试需对应依赖（gcc/onnxruntime、Postgres/Redis/嵌入式）。
- 新增模块：测试覆盖不低于 **10 个测试/模块**（项目约定）；核心模块需完整覆盖。
- 零造假红线（见 [AI协作规范.md §3](../AI协作规范.md)）：性能结论必须有基准数据，禁止凭空填写。

## 3. 单元测试约定

- 每个解析适配器独立 `*_test.go`：使用真实工具产出做数据（SCIP index、CodeGraph SQLite），覆盖空文件/大文件/语法错误边界。
- 降级路径：mock 源不可用验证回退 tree-sitter/SCIP、LSP 启动失败回退；降级后 IR 不空。
- 存储层：内存 SQLite 建表 + 基础 CRUD；多驱动（file/sqlite/pg/redis）默认栈与分支栈。
- 语义检索：向量/全文双路结果断言；embedding 用确定性子集避免不稳定。
- 运行并发包注意共享数据目录隔离（测试用各自 `t.TempDir()`）。

## 4. 核心场景（集成/Smoke）

- 单语言全链路：源文件 → 适配器 → IR → 存储 → 查询（`context`/`search_symbols`）。
- 多语言混合：多适配器协同无冲突。
- 多租户：`list_projects`/`GET /projects` 枚举、`project`/`tenant` 路由、索引隔离不串数据（`internal/integration` 有 mt 用例）。
- 影响面与测试关联：`impact`、`tests` 端到端。

## 5. CI（`.github/workflows/ci.yml`）

8 个 Job：未推代码若 CI 失败会写失败名到 commit status（便于远程读取）。提交流程见 [AI协作规范.md §5](../AI协作规范.md)。

## 6. 基准回归

```bash
make bench              # BenchmarkRealRepo_* (ScanAndIndex/Search/FullPipeline)
# 多仓库横向（非 Benchmark）
set CODESCHEMA_BENCH_REPOS="C:\repo1;C:\repo2"
go test -run=TestMultiRepo_CollectMetrics -timeout 600s ./internal/integration/
```
基准基线见 [性能调优.md](./性能调优.md) §5-6。性能/并发改动必须跑回归并记录 P95、内存。
