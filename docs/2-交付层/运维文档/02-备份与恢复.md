# 备份与恢复

> CodeSchema 的索引数据可以通过备份和恢复来避免重复扫描。

---

## 数据目录结构

```
data/
├── fts/           # 全文搜索索引（FTS JSON）
├── vector/        # 向量索引（Vector JSON）
├── idf/           # IDF 词典
└── *.json         # 文件/类/方法/调用关系等结构化数据
```

## 备份

### 方式一：Docker 卷备份

```bash
# 备份数据卷
docker run --rm -v codeschema-data:/data -v $(pwd):/backup alpine \
    tar czf /backup/codeschema-backup-$(date +%Y%m%d).tar.gz -C /data .

# 查看备份文件
ls -lh codeschema-backup-*.tar.gz
```

### 方式二：直接目录备份

```bash
# 如果使用挂载目录
tar czf codeschema-backup-$(date +%Y%m%d).tar.gz ./data/

# 压缩率参考：通常可压缩到原始大小的 30-50%
```

### 自动化备份脚本

```bash
#!/bin/bash
# backup-codeschema.sh
BACKUP_DIR="/var/backups/codeschema"
DATA_DIR="/app/data"
RETENTION_DAYS=7

mkdir -p "$BACKUP_DIR"
BACKUP_FILE="$BACKUP_DIR/codeschema-$(date +%Y%m%d-%H%M%S).tar.gz"

# 停止服务（可选，建议停止以确保一致性）
# docker compose stop codeschema

# 备份数据
tar czf "$BACKUP_FILE" -C "$DATA_DIR" .

# 恢复服务
# docker compose start codeschema

# 删除过期备份
find "$BACKUP_DIR" -name "codeschema-*.tar.gz" -mtime +$RETENTION_DAYS -delete

echo "Backup saved: $BACKUP_FILE ($(du -h $BACKUP_FILE | cut -f1))"
```

## 恢复

### 方式一：恢复 Docker 卷

```bash
# 恢复数据卷
# 1. 停止服务
docker compose down

# 2. 删除旧数据卷（可选）
docker volume rm codeschema-data

# 3. 恢复备份
docker run --rm -v codeschema-data:/data -v $(pwd):/backup alpine \
    tar xzf /backup/codeschema-backup-20260813.tar.gz -C /data

# 4. 重启服务
docker compose up -d
```

### 方式二：恢复目录

```bash
# 停止服务
docker compose down

# 恢复数据
rm -rf ./data
tar xzf codeschema-backup-20260813.tar.gz

# 重启服务
docker compose up -d
```

## 验证恢复

```bash
# 1. 检查服务健康状态
curl http://localhost:8081/health

# 2. 测试搜索
curl "http://localhost:8081/search?q=test&limit=5"

# 3. 检查索引统计
curl http://localhost:8081/metrics
```

## 注意事项

- **增量备份**：目前只支持全量备份，因为索引文件是整体 JSON 序列化
- **一致性**：建议备份前停止服务确保数据一致性
- **恢复验证**：恢复后务必执行搜索测试验证索引完整性
- **跨版本**：不同版本的 CodeSchema 索引格式可能不兼容，备份和恢复时版本须一致
