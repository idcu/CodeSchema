## 1. 环境要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| Go | 1.25+ | 仅编译时需要 |
| GCC/MinGW | 任一 C 编译器 | **仅 `-tags onnx` / `build-cgo` 需要**；默认纯 Go 构建无需 |
| Docker | 24+ | 容器化部署（推荐生产） |
| onnxruntime | 1.23.2（已验证） | 可选，ONNX 语义检索加速（动态库自动拷贝） |
| bge-small-zh-v1.5 | — | 可选，ONNX 嵌入模型（~47MB，需手动/分发下载） |

## 2. 构建

```bash
make build                 # 纯 Go，免 CGO（推荐生产）
make build-cgo             # CGO + 拷贝 ONNX 运行库（接 ONNX 需 -tags onnx）
go build -tags onnx ./...   # 启用 ONNX 语义检索（需 gcc + onnxruntime 动态库）
go build -tags pg,redis ./...  # 启用 PG + Redis
make cross                 # 5 平台交叉编译
```
产物：`build/codeschema`（Linux/macOS）、`build/codeschema.exe`（Windows）。
便捷脚本：`scripts/quick-start.sh` / `scripts/quick-start.ps1`（支持 `--docker`）。

## 3. Docker 部署

```bash
docker build -t codeschema:latest .        # Dockerfile 多阶段，GOPROXY=goproxy.cn
docker run -p 8081:8081 -v codeschema-data:/app/data codeschema:latest serve --http :8081
```

### Docker Compose（推荐生产）
```bash
cp config.yaml.example config.yaml            # 改 project.root/auth_token 等
set CODESCHEMA_AUTH_TOKEN=your-secret-token
docker compose up -d
docker compose --profile scan up              # 首次全量扫描
docker compose logs -f
docker compose down
```
> docker-compose.yml 已含健康检查、资源限制、持久化卷、一次性扫描任务的 profile scan。
> 多租户示例服务：`docker compose --profile mt up`（见 `build/mt-demo.yaml`）。

## 4. 配置与优先级

优先级：`默认值 < 配置文件 < 环境变量 < CLI 参数`。
环境变量格式：`CODESCHEMA_<SECTION>_<KEY>`，如 `CODESCHEMA_SERVER_MCP_ADDR=:9090`、`CODESCHEMA_SCANNER_WORKERS=8`、`CODESCHEMA_STORAGE_DSN=E:\data`。
完整配置项见 `config.yaml.example` 与 [配置参考](../1-生产层/配置参考.md)。

## 5. 生产部署清单（摘要）

1. 复制 `config.yaml.example` → `config.yaml`，设置 `project.name/root`。
2. **务必设置 `server.auth_token`**（禁止未授权访问）。
3. 根据规模调整 `scanner.workers`（≈CPU 核数）与 `vector_dim`（低内存 128-256）。
4. 首次先 `--profile scan` 全量扫描，再启主服务。
5. 生产建议 Nginx 反向代理 + HTTPS；每日备份 `./data`（保留 7 天，见运维手册）。
6. 存储驱动选择见技术设计 §4 规模决策（file/sqlite/pg）。

## 6. 回滚

- 容器：`docker compose pull && docker compose up -d`（旧版本通过镜像 tag 回退）。
- 二进制：保留上一版本产物，替换二进制重启即可；数据目录 `./data` 与二进制解耦，回滚不丢索引。
- 数据库迁移：`internal/store/migrations/001_init.sql`；破坏性 schema 变更需人工评审。
