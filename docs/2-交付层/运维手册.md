## 1. 数据目录结构

```
data/
├── fts/           # 全文搜索索引（FTS JSON）
├── vector/        # 向量索引（Vector JSON）
├── idf/           # IDF 词典
└── *.json         # 文件/类/方法/调用关系等结构化数据
```

## 2. 备份

**方式一：Docker 卷备份**
```bash
docker run --rm -v codeschema-data:/data -v $(pwd):/backup alpine \
    tar czf /backup/codeschema-backup-$(date +%Y%m%d).tar.gz -C /data .
```
**方式二：直接目录备份**
```bash
tar czf codeschema-backup-$(date +%Y%m%d).tar.gz ./data/
```
**自动化脚本**（保留 7 天）：
```bash
#!/bin/bash
BACKUP_DIR="/var/backups/codeschema"; DATA_DIR="/app/data"; RETENTION_DAYS=7
mkdir -p "$BACKUP_DIR"
BACKUP_FILE="$BACKUP_DIR/codeschema-$(date +%Y%m%d-%H%M%S).tar.gz"
# docker compose stop codeschema   # 建议停服保证一致性
tar czf "$BACKUP_FILE" -C "$DATA_DIR" .
# docker compose start codeschema
find "$BACKUP_DIR" -name "codeschema-*.tar.gz" -mtime +$RETENTION_DAYS -delete
```

## 3. 恢复

**Docker 卷恢复**：`docker compose down` → `docker volume rm codeschema-data`（可选）→ 解包到卷 → `docker compose up -d`。
**目录恢复**：停服 → `rm -rf ./data` → `tar xzf codeschema-backup-*.tar.gz` → 重启。

**恢复验证**（必须执行）：
```bash
curl http://localhost:8081/health
curl "http://localhost:8081/search?q=test&limit=5"
curl http://localhost:8081/metrics
```

## 4. 备份注意事项

- 目前仅支持**全量备份**（索引为整体 JSON 序列化）。
- 备份前建议停服保证一致性；恢复后务必跑搜索验证。
- **跨版本**：不同版本索引格式可能不兼容，备份/恢复版本须一致。

## 5. 监控指标（Prometheus，纯 Go 自研 metrics）

端点 `GET /metrics`，格式兼容 Prometheus text exposition。指标：`http_requests_total`（method,path,status）、`http_active_requests`、`scanner_processed_total/scanner_files_total/scanner_errors_total/scanner_active_workers`、`analyzer_*`、`parser_fallback_total`（降级回退）、`lsp_*`（C/C++ 缺 compile_commands、空符号、重试、畸形帧等）。

采集配置：
```yaml
scrape_configs:
  - job_name: 'codeschema'
    scrape_interval: 15s
    metrics_path: '/metrics'
    static_configs: [{ targets: ['localhost:8081'] }]
```

## 6. 结构化日志（log/slog）

JSON 格式，必选字段 `timestamp/level/module/msg`，常用 `file/latency_ms/error/language/adapter`。
Loki/ELK 接入：docker-compose 为 codeschema 服务加 `logging.driver: loki`，`loki-url` 指向 Loki。

## 7. 健康检查端点

`/health`（整体）、`/health/db`、`/health/vector`、`/health/kv`。健康检查脚本见 `docs/ops/03`。

## 8. 告警规则（Alerts）

```yaml
rules:
  - alert: CodeSchemaDown
    expr: up{job="codeschema"} == 0
    for: 1m
    labels: { severity: critical }
  - alert: HighErrorRate
    expr: rate(http_requests_total{status=~"5.."}[5m]) > 0.05
    for: 5m
    labels: { severity: warning }
  # HighLatency：P95 > 1s 需在实现延迟指标后启用
```

Grafana 推荐面板：请求量 `rate(http_requests_total[5m])`、活跃请求、5xx 错误率、`topk` 端点分布。

## 9. 需重点关注的日志事件

| 关键词 | 级别 | 说明 |
|---|---|---|
| `panic recovered` | ERROR | 服务内部 panic |
| `scan failed` | ERROR | 扫描失败 |
| `build index` | WARN | 索引构建警告 |
| `health check` | WARN | 健康检查异常 |
| `fallback` | WARN | 功能降级（如向量搜索不可用回退内存模式） |
