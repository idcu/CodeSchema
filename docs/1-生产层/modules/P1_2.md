# P1_2 MCP Server

> 模块编号：P1_2 ｜ 父模块：P1 接入层 ｜ 完成度：100% ｜ 代码：`internal/server/mcp.go` + `mcp_stdio.go`

## 🎯 模块用途

面向 AI Agent 的核心交付面。通过 MCP（Model Context Protocol）协议向 Claude Code / Cursor / VS Code / JetBrains 等 AI 客户端供给精准裁剪后的代码上下文，解决「AI 回答代码问题需要喂入整个仓库」的 token 浪费问题。

## 🧱 拆分逻辑说明

按**技术分层（协议入口）**独立：MCP 是 JSON-RPC 2.0 双向协议（SSE + stdio 两种传输），生命周期长驻、需要鉴权，与一次性 CLI 命令、REST 请求/响应形态完全不同，独立成模块便于协议演进与客户端兼容维护。

与 P1_3 HTTP 的边界：MCP 面向 AI 工具调用（工具/参数/结果的结构化往返），HTTP 面向脚本与浏览器（REST 资源语义）。

## ⚙️ 技术说明

**技术选型**：手写 JSON-RPC 2.0（无 MCP SDK 依赖）；SSE（Server-Sent Events）流式输出 + stdio 传输（`--stdio` 供仅支持 stdio 的客户端直连）；Bearer token 鉴权（`--auth-token`）。

**对外接口契约（12 个 MCP 工具）**：

| 工具 | 用途 |
|---|---|
| `search_symbols` | 按符号名搜索类/方法 |
| `context` | 获取符号所在文件的上下文裁剪 |
| `impact` | 影响面分析（改一处反查受影响方法） |
| `tests` | 关联单测查询 |
| `affected` | 受影响符号列表（可递归） |
| `find_dependencies` | 符号依赖查询 |
| `get_call_graph` | 调用图获取 |
| `get_tags` / `search_by_tag` / `get_all_tags` | 标签体系三类操作 |
| `search_config` | 配置检索 |
| `list_projects` | 枚举多租户项目（tenant 路由） |

辅助能力：`mcp --print-config` 输出各客户端接入配置；启动时自动全量建索引 + IDF 自动持久化（60s 间隔）。

**依赖的下层模块**：P2_1 Service（全部工具透传）、P2_2 Scanner 不直接依赖（服务启动建索引走 Service.BuildIndex）、P5_1 检索、P8 公共模块。

**数据模型**：JSON-RPC 请求/响应信封（`jsonrpc`/`id`/`method`/`params`），工具参数 Schema 自描述。

## 🔄 替代方案

- 官方 MCP Go SDK（`mark3labs/mcp-go` 等）：协议版本升级自动兼容，但引入外部依赖、增加二进制体积；当前工具集固定、协议面简单，手写可控性更强。
- 纯 stdio 单传输：简化实现但丢失 SSE 远程接入能力，不满足「`--addr :8080` 远程供给」的核心诉求。
