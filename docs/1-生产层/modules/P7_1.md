# P7_1 Store 接口 + 文件存储

> 模块编号：P7_1 ｜ 父模块：P7 存储层 ｜ 完成度：100% ｜ 代码：`internal/store`（store.go / filestore.go / upsert.go / filelock_*.go / migrations/）

## 🎯 模块用途

定义存储层**统一接口契约**（`Store`），并提供默认的 JSON 文件实现（`FileStore`）与批量写入优化（`BulkUpsert`）。是「驱动可插拔」的地基——所有上层只面向接口编程。

## 🧱 拆分逻辑说明

按**技术分层（契约 + 默认实现）**独立：接口定义与 file 实现放在核心包；sqlite/pg/redis 作为子包实现同一接口。`filelock_unix/windows` 为跨平台文件锁（并发写保护）；`migrations/` 为 SQL 迁移目录。

## ⚙️ 技术说明

**技术选型**：Go 标准库 `encoding/json` + `os`；`golang.org/x/sys/unix`（文件锁）。

**对外接口契约**：`store.Store` 完整接口（见 P7 技术说明，不重复）+ `NewStore(driver)`（仅分发 file，其余驱动由 cmd 层接线）。

**依赖的下层模块**：P3_1（IR 结构）。
**被依赖方**：P7 全部驱动（实现方）、P2/P4/P5 业务层。

**数据模型**：`FileRecord{ID, AbsolutePath, ContentHash, LineCount, ByteSize, ReferencedByFiles, Imports, Language, ParseStatus}` 等记录结构。

## 🔄 替代方案

- 无接口直连 FileStore：驱动无法插拔，SQLite/PG 接入需要改所有上层，不可取。
- JSON 存储改 gob/msgpack：二进制更快但不可读、难调试；当前 JSON + BulkUpsert 满足需求。
