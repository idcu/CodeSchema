# P4_1 代码图与影响面分析 Analyzer

> 模块编号：P4_1 ｜ 父模块：P4 分析层 ｜ 完成度：100% ｜ 代码：`internal/analyzer`（analyzer.go / graph.go / resolver.go）

## 🎯 模块用途

基于 Store 中已入库的 IR 记录，在内存中构建**四张图**——调用图（CallGraph）、类层次（ClassHierarchy）、反向引用索引（ReverseIndex）、文件图（FileGraph），并提供影响面分析（FindImpactNodes）、最短路径、模块摘要与规则标签推导（TagAll）。是「改一行反查受影响方法并定位关联单测」能力的基础。

## 🧱 拆分逻辑说明

按**职责边界（确定性图推理）**独立：与 AI 增强（P4_2，非确定性）分离，保证核心推理不依赖外部服务、可单测可离线运行。内部按图结构拆为 analyzer.go（编排）、graph.go（四种图数据结构的构建）、resolver.go（Go/Java/Gradle 模块路径解析，用于跨模块引用定位）。

## ⚙️ 技术说明

**技术选型**：纯 Go；BFS/DFS 图遍历 + 多源路径解析器（CompositeResolver）。

**对外接口契约**：

| 方法 | 说明 |
|---|---|
| `BuildAll` / `BuildCallGraph` / `BuildClassHierarchy` / `BuildReverseIndex` / `BuildFileGraph` | 建图 |
| `FindImpactNodes(ctx, methodFQN, depth)` | 影响面（callers + callees） |
| `ShortestPath(ctx, from, to)` | 调用路径 |
| `TagAll(ctx)` | 全量规则标签推导（六类：layer/biz/tech/risk/test/lang） |
| `Analyze(ctx)` | 模块摘要 |
| `NewGoResolver`/`NewJavaResolver`/`NewGradleResolver` | 模块路径解析器 |

**依赖的下层模块**：P7 存储层（读 class/method/call/tag 记录）、P3_1（IR 结构）、P4_2（可选 Enhancer 注入，标签补全）、P8 公共模块。

**数据模型**：`CallGraph`（caller→callee 边）、`ClassHierarchy`（ParentFQNs 派生）、`ReverseIndex`（符号→引用方）、`FileGraph`（文件间 import/include 关系）；`ImpactNode`（带深度）。

## 🔄 替代方案

- 图构建实时从 Store 全量读取：数据量大时慢，当前按需构建 + 内存驻留是合理取舍。
- 外部图数据库（neo4j/dgraph）：持久化更强，但对单机场景过重，且引入部署复杂度，当前内存图 + 重新 Build 足够。
