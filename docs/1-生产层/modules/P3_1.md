# P3_1 解析核心（IR 模型 + 注册机制）

> 模块编号：P3_1 ｜ 父模块：P3 解析层 ｜ 完成度：100% ｜ 代码：`internal/parser`（ir.go / registry.go / plugin.go / fallback.go）

## 🎯 模块用途

定义解析层的**统一数据契约（IR）**与**插件注册机制**。解决「多语言解析器各产各的、无法统一入库」的问题：所有适配器必须把结果归一化为 `IRDocument`，通过 `Registry` 注册/分发，核心本身不做任何具体语言解析。

## 🧱 拆分逻辑说明

按**技术分层（契约层）**独立：IR 是跨模块共享的「代码元数据 Schema」——Store 按它建表、Search 按它建索引、Analyzer 按它建图。把它独立成模块后，新增语言解析器不触碰任何下游代码；IR 字段变更则全链路感知（被 8 个包依赖）。

与适配器的边界：核心管「定义 + 分发」，适配器管「实现」。核心不 import 任何适配器包。

## ⚙️ 技术说明

**技术选型**：纯 Go；无第三方依赖（语言扩展名映射在 `adapter` 子包）。

**对外接口契约（核心数据结构）**：

```go
IRDocument{ Source, Language, FilePath, FileHash, CommitHash,
             LineCount, ByteSize, ReferencedBy, Classes, Methods, Calls, Imports }
ClassIR{ Name, FullName, Type(CLASS/INTERFACE/ABSTRACT/ENUM),
         ParentFQNs, StartLine/Col, EndLine/Col, Modifier, Doc, Annotations, Extra }
MethodIR{ Name, Signature, ReturnType, ClassFQN, 位置, Modifier, Doc,
          Annotations, IsStatic/IsAbstract/IsConstructor, Params, Extra }
ParamIR{ Name, Type, Index, Annotation }
CallIR{ CallerFQN, CalleeFQN, CallType(direct/interface/dynamic/unknown), LineNumber }
```

- `ParserPlugin` 接口：适配器实现并注册
- `Registry`：按语言/来源分发解析器；无匹配时走 `fallback`
- `adapter.SupportedLanguages()`：31 种语言常量

**依赖的下层模块**：P8_2 日志、P8_3 指标。

**数据模型**：见上方 IR 结构（本项目最重要的共享数据契约）。

## 🔄 替代方案

- 每种语言一个独立 IR：下游按语言分叉处理，Store/Search 无法统一，不可取。
- 用 protobuf 定义 IR：强类型跨语言更稳，但当前全 Go 单栈，结构体 + `Extra map[string]any`（JSONB 兜底语言差异）足够。
