# P8_4 链路追踪 【公共模块】

> 模块编号：P8_4 ｜ 父模块：P8 横切公共模块 ｜ 完成度：100% ｜ 代码：`internal/trace`（trace.go 221 行）

## 🎯 模块用途

提供轻量**链路追踪**能力：在扫描、分析、服务查询的跨组件调用间传播 trace id/span，记录关键阶段的耗时。解决「一次查询在哪个环节慢、一次扫描卡在哪」的定位问题。

## 🧱 拆分逻辑说明

按**职责边界（横切能力）**独立：追踪埋点横跨 scanner→parser→store、server→service→search 两条链路，独立成模块让埋点接口稳定、实现可替换（未来可接 OpenTelemetry）。

## ⚙️ 技术说明

**技术选型**：自研 span/trace 结构（id 生成 + 父子关系 + 耗时），基于 `internal/log` 输出。

**对外接口契约**：`Trace`/`Span` 类型 + 开始/结束/耗时 API；context 传播。

**依赖的下层模块**：P8_2 日志。

**数据模型**：span 树（trace_id/span_id/parent/duration）。

## 🔄 替代方案

- OpenTelemetry Go SDK：生态标准、可接 jaeger/otlp，但对单服务接入成本高；自研轻量追踪已满足「定位慢环节」，未来可替换实现而不动接口。
