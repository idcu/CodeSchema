# P7_4 Redis 热点缓存

> 模块编号：P7_4 ｜ 父模块：P7 存储层 ｜ 完成度：85% ｜ 代码：`internal/store/redis`（redis.go 106 行）

## 🎯 模块用途

为**热点查询**（类/调用反查）提供 Redis L2 缓存层，降低权威存储的读压力。`storage.kv=redis://host:6379/0` 配置后启用（需 `-tags redis` 构建）；地址为空则不启用。

## 🧱 拆分逻辑说明

按**职责边界（读缓存横切）**独立：缓存是横切于权威存储（file/sqlite/pg）之上的读加速层，与权威存储解耦——缓存可单独启停、失效不影响正确性（穿透回权威存储）。`-tags redis` 隔离保证默认构建零依赖。

## ⚙️ 技术说明

**技术选型**：`github.com/redis/go-redis/v9`；`-tags redis` 条件编译。

**对外接口契约**：实现 `store.Store`（热点路径走缓存：类记录/调用反查，缓存穿透回权威存储）。

**依赖的下层模块**：P7_1（Store 接口）、`go-redis/v9`。
**外部服务**：Redis 实例（连接串 `storage.kv`）。

**数据模型**：热点 key → 序列化记录（TTL 由缓存策略控制）。

## 🔄 替代方案

- 不做缓存层：读热点全部压权威存储，亿级场景不可行。
- 应用内 LRU 缓存：单机有效但多实例不共享；Redis 是分布式正解。
