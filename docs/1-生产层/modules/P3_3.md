# P3_3 SCIP 适配器

> 模块编号：P3_3 ｜ 父模块：P3 解析层 ｜ 完成度：97% ｜ 代码：`internal/parser/adapter/scip`

## 🎯 模块用途

消费 **SCIP（Sourcegraph Code Intelligence Protocol）索引文件**提取符号与调用关系。SCIP 是编译期/工具期产出的高精度索引格式（如 `scip-java` 索引器），在需要极高解析精度的场景（Java/TS 大型仓库）替代正则解析。

## 🧱 拆分逻辑说明

按**数据来源（编译产物索引）**独立：SCIP 索引由外部索引器生成，本模块只负责解析索引文件为 IR——是「外部高质量数据源接入」的典型乐高积木，与 Treesitter（自带解析）、LSP（运行时语言服务）形成互补。

## ⚙️ 技术说明

**技术选型**：纯 Go protobuf 解析（SCIP 索引为 protobuf 二进制，手写极简 wire 解码器 `scipwire.go`，零外部依赖）；`internal/errors` 错误体系。

**对外接口契约**：实现 `parser.ParserPlugin`；按 SCIP 索引文件路径解析，产出 `IRDocument`（class/method/**调用关系提取**已端到端测试覆盖）。

**依赖的下层模块**：P3_1 解析核心、P8_5 错误体系。

**数据模型**：SCIP `Document`/`Symbol`/`Occurrence` 结构 → `parser.IRDocument`。

## 🔄 替代方案

- 直接用 Sourcegraph 全家桶：功能强但重，本系统只需 IR 提取，独立解析更轻。
- 不用 SCIP、全靠 Treesitter：对大型 Java 仓库精度不足，SCIP 是高精度补充。
