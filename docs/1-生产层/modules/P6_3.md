# P6_3 模型分发与下载

> 模块编号：P6_3 ｜ 父模块：P6 向量索引层 ｜ 完成度：97% ｜ 代码：`internal/vector`（model_download.go / model_registry.go）

## 🎯 模块用途

管理 ONNX 语义模型文件的**生命周期**：按需远程下载、SHA-256 完整性校验、幂等确保（已存在则跳过）、内置模型注册表回填下载 URL。解决「模型文件（~47MB）不该打进二进制、也不该让用户手工下载」的分发问题。

## 🧱 拆分逻辑说明

按**职责边界（文件生命周期管理）**独立：模型下载是 IO/网络密集且幂等的操作，与运行时嵌入推理（P6_2）解耦——嵌入器启动时只调 `Ensure()`，下载逻辑失败也不影响降级路径。

## ⚙️ 技术说明

**技术选型**：Go 标准库 `net/http` + `crypto/sha256` + `archive/tar`/`compress/gzip`（模型包解压）。

**对外接口契约**：
- `NewModelDownloader(modelDir, downloadURL, sha256)` — 配置 URL 与校验和（URL 未配置时查内置注册表回填）
- `Ensure(ctx, modelName) (bool, error)` — 幂等确保模型就位（已存在跳过，缺失则下载 + 校验 + 解压）

**依赖的下层模块**：P8_2 日志。

**数据模型**：模型目录结构（`down/models/<embedding_model>`）；注册表（模型名 → 默认 URL/SHA256）。

## 🔄 替代方案

- 模型打进 Docker 镜像：镜像体积暴涨（+47MB+），且跨语言模型更新需重建镜像。
- 用户手动下载：接入门槛高、易出错；自动分发 + 校验是正确取舍。

## 📊 完成度：97%

已做：远程下载、SHA-256 校验、幂等确保、内置注册表（URL 回填）、**公网分发闭环**（`make models-serve` 本地 HTTP 分发源 + 真实制品端到端验证）、**HTTP Range 断点续传**（`.download.part` 落盘 + 206/200 自适应 + 完整 `.part` 复用，中断重下不浪费已下载部分）、自动降级衔接。
未做：多模型注册表扩充（持续演进项）。

## 🚧 阻塞与风险

- 下载依赖网络可达的模型源——离线环境需预置模型文件（已有降级路径）；断点续传缓解弱网/中断场景。
- 下载失败仅记日志并降级 Local，需确保**不阻塞主流程**（当前已保证）。
