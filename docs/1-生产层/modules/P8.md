# P8 横切公共模块（Cross-cutting）【公共模块】

> 模块编号：P8 ｜ 父模块：无（一级） ｜ 完成度：100%

## 🎯 模块用途

承载被多个业务模块共享的**零业务语义横切能力**：配置、日志、指标、追踪、错误、健壮性（重试/优雅关闭/Panic 恢复）。解决「同样的日志/重试/错误处理在每个业务包里重复实现」的问题，是乐高积木里的**标准件**——不承载任何业务，但每个业务积木都要插它。

## 🧱 拆分逻辑说明

按**职责边界（横切能力）**划分，六个子模块各管一类能力，互不依赖（除了 trace 依赖 log、robust 依赖 log 这类薄依赖）。判定「公共模块」的标准：**被 ≥2 个业务模块依赖**。六个子模块全部满足。

## ⚙️ 技术说明

**技术选型**：Go 标准库为主——`log/slog`（日志）、Prometheus 文本格式（指标，手写）、`runtime/debug`（Panic 恢复）、`context` + `os/signal`（优雅关闭）、`math/rand` + `time`（指数退避重试）。

**对外接口契约**：见各子模块。

**依赖的下层模块**：无业务依赖（仅公共模块间薄依赖）。
**被依赖方**：覆盖全部业务层（见下方表格）。

**数据模型**：无。

## 🔄 替代方案

- 引入 zap/zerolog（日志）、otel-go（追踪）、Prometheus client-go（指标）：生态更全，但当前需求用标准库即可达成且零依赖；otel 全家桶对单服务过重。
- 公共能力下沉进业务包：必然重复，不可取——独立公共模块是既定原则。
