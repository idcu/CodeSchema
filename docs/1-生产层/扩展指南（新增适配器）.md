## 1. 体系概览

适配器层是系统核心扩展点，通过 `ParserPlugin` 接口接入多种解析源：

| 适配器 | 形态 | IR 覆盖 | 说明 |
|---|---|---|---|
| `treesitter` | 源文件 | class/method + 行号 + 简单调用名（30 语言） | 通用兜底，纯 Go 正则启发式，无 CGO；调用检测全语言启用 |
| `scip` | SCIP index（批量） | class/method + 精确引用边 | 首选精确数据源；流式加载 + 文档背压 |
| `jdtls` | Java（LSP 子进程） | 符号 + references | 需 JDK 17+ |
| `clangd` | C/C++（LSP 子进程） | 符号 + references | 需 `compile_commands.json` |
| `gopls` | Go（LSP 子进程） | 符号 + references | Go 官方 LSP |
| `codegraph` | CodeGraph SQLite（批量） | 直读 symbols/edges | 竞品产出直读；源不可用降级 tree-sitter |
| `jcodeindexer` | JCodeIndexer SQLite（批量） | 直读符号表 | 竞品产出直读（仅配置预留，未实现） |

每个适配器为独立子包 `internal/parser/adapter/<name>`，可单独编译/测试/启停。系统仅消费产出或通过子进程调用 LSP，**不内嵌任何竞品代码**。

## 2. 按语言择优

| 语言 | 首选 | 精确语义 | 兜底 |
|---|---|---|---|
| 通用多语言 | tree-sitter（`-tags treesitter`，CGO） | 语法级 | 正则启发式（默认） |
| Go | gopls | 是 | tree-sitter |
| Java/Scala/Kotlin | jcodeindexer + jdtls + scip-java | 是 | tree-sitter |
| C/C++ | clangd + scip-clang | 是 | tree-sitter |
| TypeScript/JavaScript | scip-typescript / tsserver | 是 | tree-sitter |
| Python | scip-python / pyright | 是 | tree-sitter |
| Rust | rust-analyzer | 是 | tree-sitter |

## 3. 降级策略

- 由 `parser.NewFallbackParser` 包装（`internal/parser/fallback.go`）：当前适配器返回 `ErrSourceUnavailable` → 自动回退 tree-sitter/SCIP → **最多降级 1 次**。
- 路径：`CodeGraph/JCodeIndexer SQLite 不可用 → tree-sitter/SCIP`；`LSP 子进程启动失败 → tree-sitter`。
- 可观测：触发降级计数 `parser_fallback_total`；LSP C/C++ 无 `compile_commands.json` 时 `lsp_missing_compile_commands_total`（可能静默空符号）。

## 4. 新增语言扩展步骤（Kotlin/Swift/PHP 已落地范式）

1. `adapter.ExtToLang` 增加扩展名映射（如 `.kt`/`.kts` → `kotlin`）。
2. `internal/parser/adapter/treesitter/initPatterns` 增加 `langPatterns`（class/method/call 正则 + commentTrim）。
3. `scanner.detectLang` 与 `adapter.SupportedLanguages` / `LangToExtensions` 同步。
4. 补 Parse 单测（见 §6）。

> 精度档位与 tree-sitter 真语法树（CGO）方案评估见 `analysis/2026-08-14-t2-1-parser-precision-eval.md`。

## 5. 实现步骤（以新适配器为例）

### 5.1 tree-sitter（`-tags treesitter`）
- 创建 `internal/parser/adapter/treesitter/`，实现 `ParserPlugin`（`Name/Supports/Init/Close/Parse`）。
- `go-tree-sitter` 绑定 + 按扩展名加载纯 Go 文法（编译进二进制，无 `.so`）；遍历 CST 提取 class/method 行号区间与简单调用；组装 `IRDocument`。
- 大文件（>10MB）用 context 控制超时；无法识别的扩展名返回空 IR（非错误）。

### 5.2 SCIP（批量）
- 实现 `BatchParser`（`ParseAll` 流式加载 index、文档背压）；解析 `Document` 列表按文件分发 IR，提取精确 `Reference` 边。输入由外部工具（scip-java/go/clang/typescript）生成。

### 5.3 LSP（jdtls/clangd/gopls）
- 子进程 stdin/stdout JSON-RPC 通信；`initialize` → `didOpen` → `documentSymbol`/`references` → `didClose`；解析响应组装 IR。注意 LSP JSON-RPC `omitempty` 约束（notification 不得携带 id）。

### 5.4 竞品直读（CodeGraph/JCodeIndexer）
- `database/sql` + `modernc.org/sqlite` 只读打开竞品库；查询 symbols/edges 表按文件分组；DB 不存在/格式错误返回 `ErrSourceUnavailable` 触发降级。

### 5.5 注册与接线
- 在注册中心 `Select` 方法实现优先级降级；经 `config.parser.adapters` 列表启用。

## 6. 测试要求（每个适配器独立 `*_test.go`）

- 使用真实工具产出做测试数据（SCIP index、CodeGraph SQLite 等）；覆盖空文件/大文件/语法错误边界。
- 降级路径：mock 竞品源不可用 → 验证降级 tree-sitter/SCIP 且 IR 不空；mock LSP 启动失败 → 降级 tree-sitter。
- 集成：单语言全链路、多语言混合、降级路径各一。
