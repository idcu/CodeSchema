# 架构与模块

> 写给：要理解内部结构与扩展点的开发者

> 最后更新：2026-09-02
## 分层（自上而下）

1. **入口层** `cmd/codeschema`：子命令分发 `scan` / `watch` / `rebuild-kv` / `benchmark` / `agent-bench` / `mcp` / `serve` / `version`（8 个，详见下方「子项清单」）；build-tag 统一分发存储后端（避免 `store` 包循环依赖）。
2. **服务层** `internal/service`：`service.go`（上下文裁剪）、`testlink.go`（单测关联）、`coverprofile.go`（覆盖率）。
3. **接口层** `internal/server`：HTTP REST（`http.go`）+ MCP（`mcp.go` / `mcp_stdio.go`）+ `middleware.go`（CORS/recovery/认证/限流）+ OpenAPI（`openapi_handler.go`）+ 可视化（`viz.go`）。
4. **检索层** `internal/search` · `retrieval` · `vector` · `embedding`：精确符号图 + 全文（FTS）+ 向量语义 + 置信度过滤。
5. **数据层** `internal/store`：统一 `Store` 接口，四种后端（见[存储后端](./存储后端.md)）。
6. **解析层** `internal/parser/adapter`：多语言适配器（见[解析适配器](./解析适配器.md)）。
7. **支撑** `analyzer`（调用图建边）、`scanner`（扫描编排）、`watcher`/`fswatch`（增量）、`scheduler`、`tenant`（多租户）、`config`、`ai`（AI 增强与规则标签）。

## 模块树（按职责）

```
cmd/codeschema
internal/
├── parser/adapter/   {treesitter, codegraph, scip, lsp}   # + jcodeindexer 经配置启用
├── scanner/          # 扫描编排，并发 worker
├── analyzer/         # 调用关系建边（CallerFQN 回填核心）
├── store/ (+sqlite, +pg, +redis build-tags)
├── service/          # context / testlink / coverprofile
├── server/           # http / mcp / mcp_stdio / middleware / openapi / viz
├── search|retrieval|vector|embedding   # 检索与语义
├── tenant/           # 多租户隔离
├── watcher|fswatch/  # 增量监听（fsnotify / 轮询）
├── scheduler/        # 任务调度
├── ai/               # AI 增强（规则标签、预算）
├── config/ runtime/ lock/ hash/ errors/ …  # 基础设施
```

## 子项清单（cmd / internal）

> 开发者最关心的两块：入口子命令与内部包职责。完整逐目录下钻（docs / scripts / contrib / down / build …）见 [仓库结构.md](../仓库结构.md)。所有条目均按 `cmd/codeschema/main.go` 与 `internal/` 源码实地核查，并经 `make counts` 校验（internal=32 / total=36 / mcp=12 / http=16）。

### cmd/codeschema 子命令（8 个）

| 子命令 | 作用 |
|---|---|
| `scan <path>` | 全量扫描仓库并入库（解析 → 索引 → IDF → 标签推导） |
| `watch <path>` | 文件监听增量（默认轮询，`--fsnotify` 切原生监听） |
| `rebuild-kv` | 重建 KV 缓存（P2） |
| `benchmark` | 全链路基准（扫描 / 索引 / 检索指标，多仓库对比） |
| `agent-bench` | Agent 端到端基准（实现于 `benchmark.go:126`，未在 `-h` 用法列出） |
| `mcp` | 启动 MCP Server（SSE，可选 `--stdio` 直连） |
| `serve` | 启动 HTTP API Server（可选同进程起 MCP） |
| `version` | 显示版本信息 |

### internal/ 顶层包（26 个；含嵌套子包共 32 个 internal Go 包，以 `make counts` 为准）

- `scanner` 仓库扫描调度
- `parser` 解析适配器注册中心（tree-sitter 兜底 + LSP / SCIP / CodeGraph 高精度优先；适配器实现见 `parser/adapter`）
- `store` 存储后端接口 + file / sqlite 实现（pg / redis 经 build-tag 接线，为嵌套子包）
- `server` MCP / HTTP 服务 + 向量索引可视化 `/viz`
- `service` 业务编排（BuildIndex / RunTagAll / 单测关联 / 覆盖率）
- `runtime` 运行期组件装配（NewSearcher / NewParserRegistry / WithImpactAnalyzer / RunTagAll）
- `tenant` 多租户管理（单进程服务多个隔离仓库）
- `config` 配置加载、环境变量覆盖、热重载
- `search` FTS 双路检索 / rerank
- `vector` 向量存储与索引
- `embedding` 文本嵌入管线
- `retrieval` 召回 / 检索抽象
- `analyzer` 影响面 / 依赖分析（调用图建边、CallerFQN 回填）
- `scheduler` 增量调度（debounce 队列）
- `watcher` 轮询 / fsnotify 监听实现
- `fswatch` 文件监听（fsnotify 封装）
- `ai` AI 增强（标签 / 上下文增强）
- `benchmark` 全链路基准框架
- `scalebench` 规模基准（多量级 sqlite）
- `adapterbench` 解析适配器基准对比
- `agentbench` Agent 端到端基准
- `integration` 集成测试辅助
- `testutil` 测试工具
- `errors` 统一错误类型
- `hash` 哈希工具
- `lock` 分布式 / 文件锁

## 关键数据流

```
scan ./repo
  → scanner（worker 并发）
  → parser/adapter（按语言选适配器，产出 IR：类/方法/调用）
  → analyzer（建调用边，需 CallerFQN）
  → store.UpsertIR / BulkUpsert（落库 + 内存/向量索引）
查询 context/impact/search
  → server（鉴权/限流）→ service（裁剪/关联）→ store/search（检索）
```
