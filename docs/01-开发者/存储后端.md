# 存储后端

> 写给：要切换/扩展存储的开发者

> 最后更新：2026-09-03

## 统一接口

`internal/store.Store` 抽象所有存储操作（Upsert/Get/Tag/Search/HealthCheck…）。后端经 `cmd/codeschema` 的 build-tagged 分发接线——因 `pg`/`redis` 子包反向依赖 `store` 包，分发必须落在 cmd 层，不能在 `store.NewStore` 内（否则循环依赖）。

## 四种后端

| 驱动              | 配置                                               | 构建标签          | 说明                                       |
| --------------- | ------------------------------------------------ | ------------- | ---------------------------------------- |
| `file`（默认）      | `storage.driver=file`                            | 无             | JSON 文件，零依赖，跨会话弱                         |
| `sqlite`        | `storage.driver=sqlite`                          | 无             | modernc.org/sqlite 纯 Go 免 CGO，关系查询/跨会话一致 |
| `pg`/`postgres` | `storage.driver=pg` + `storage.dsn=postgres://…` | `-tags pg`    | PostgreSQL，亿级横向扩展                        |
| Redis 缓存层       | `storage.kv=redis://host:6379/0`                 | `-tags redis` | 热点类/调用 L2 缓存（CacheReader 反查），空则不启用       |

## Schema 一致性说明（改库前必读）

运行时 **不会加载** `internal/store/migrations/001_init.sql`（其定位为设计参考，非执行 DDL）。各后端 schema 以内联 DDL 为准，且**后端之间并不一致**：

- **默认 SQLite**（`internal/store/sqlite/sqlite.go`）：**FQN 型轻量 schema**（file/class/method/call/tag/class\_tag/method\_tag），类继承用 `class.parent_fqns`(JSON)，`call` 用 `caller_fqn/callee_fqn`(文本)，**无** project/class\_parent/parameter/ret\_type/method\_test\_link 表。

- **PG**（`internal/store/pg/pg.go`）：**14 表 ID 型**（含 project/class\_parent/parameter/ret\_type/method\_test\_link，以及 2026-09-03 新增的变量表 `field`、常量表 `constant`），`call` 同样用 `caller_fqn/callee_fqn`（与 001\_init.sql 的历史 `caller_method_id` 版不同，以代码为准）。

- 影响面/调用链均以 **FQN 串接**（caller\_fqn→method），而非 method id 外键。

- **FK 约束（2026-09-03 落地，仅 PG）**：必填且必有目标的列加 `FOREIGN KEY ... ON DELETE CASCADE`（file.project\_id / class.file\_id / method.class\_id / parameter.method\_id / ret\_type.method\_id / call.file\_id / class\_parent.class\_id / class\_tag.\* / method\_tag.\* / method\_test\_link.\* / field.class\_id·method\_id / constant.file\_id·class\_id）；删除 file/class/method 时级联清理从属数据。可空兜底列不加 FK（`class.parent_class_id` 靠 parent\_fqn 兜底、`call.caller/callee_fqn` 为 FQN 文本）。

- **field / constant 归属二选一**（CHECK 约束）：field 只挂 class（成员变量）或 method（局部变量）之一；constant 只挂 file（包/文件级）或 class（类级）之一。类级常量可复用 field(is\_const=1)。注意 DDL 用 `CREATE TABLE IF NOT EXISTS`，**仅对新建库生效**，既有旧库需手工 `ALTER TABLE ADD CONSTRAINT` 迁移。

> 需跨后端共用而改 schema 时：同步修改 `001_init.sql`、`sqlite.go`、`pg.go` 三处内联 DDL，避免文档与代码漂移。
> 其余行为级变更（`UNIQUE(project_id, absolute_path)`、`method.return_type`/`ret_type` 归一化等）属破坏性改动，按 AGENTS.md 需先评审 + 回归后再落地。

## 写入性能事实（`scalebench` 实测，N=10万）

- 逐文件 `UpsertIR`：SQLite ≈ **77–237s**（事务提交放大），JSON FileStore ≈ **0.4s**（慢约 500×）。

- **已用** **`BulkUpsert`（单事务 + 预编译）修复**：100k 落库降至约 **5–14s**（约一个数量级提速）。

- 结论：生产化用 `BulkUpsert`；超大仓/亿级切 PG；**「SQLite 慢于 JSON」是写入事实，但 SQLite 的关系查询/一致性是 JSON 不具备的**。

## 标签与检索

- 标签分类六类：`layer`/`biz`/`tech`/`risk`/`test`/`lang`，由 `DeriveTagCategory` 统一推导（三后端共用口径）。

- 检索：`fts`（全文，纯 Go 实现）+ `semantic`（向量）+ 融合重排；置信度低于 `min_score` 的结果被过滤（见[架构师文档](../02-架构师/README.md)）。
