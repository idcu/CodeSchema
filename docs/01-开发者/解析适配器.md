# 解析适配器

> 写给：要新增语言支持或理解解析行为的开发者

> 最后更新：2026-09-03
## 适配器总览

解析层 `internal/parser/adapter` 按语言/精度选择适配器，产出统一 IR（类/方法/调用关系）：

| 适配器 | 精度 | 启用方式 | 备注 |
|---|---|---|---|
| `treesitter` | 中（默认） | 始终注册（兜底，无需配置） | 正则启发式，30 语言，零 CGO；`-tags treesitter` 切真语法树 |
| `codegraph` | 高 | `parser.codegraph.db` 配置 | 接 CodeGraph 索引库 |
| `scip` | 高 | `parser.scip.index_dir` | SCIP index |
| `lsp` | 高 | `parser.lsp.enabled: true` | 按语言分发 gopls/jdtls/clangd/rust-analyzer/pyright-langserver/typescript-language-server；缺失自动回退 tree-sitter |

> **`parser.adapters` 为声明性清单**：`internal/runtime/runtime.go` 的 `NewParserRegistry` 始终注册 tree-sitter（兜底），并按 `parser.lsp.enabled` / `parser.scip.index_dir` / `parser.codegraph.db` 注册高精度适配器；`parser.adapters` 数组当前**不作为注册开关被消费**，仅作声明/文档登记（以代码为准）。

> **LSP e2e 运行环境（遗留② 已验证）**：`docker/lsp-test/Dockerfile` 已内置 Java/C++ 的 LSP 服务器——`jdtls`（Eclipse JDT LS 快照，依赖 `default-jdk`，debian:trixie 默认 JDK 即 21，满足最新 jdtls 快照的 class file 65.0）与 `clangd`（含 `clang`/`compile_commands.json` 能力），可实跑 Java/C++ LSP 端到端测试；此外含 gopls / rust-analyzer / pyright / typescript-language-server / scip / codegraph 等工具。

> **`jcodeindexer` 为配置预留、尚未实现**：`parser.jcodeindexer` 仅是 `config.yaml` 的配置字段（见 `internal/config/parse.go`），目前**无对应适配器实现**（`internal/parser/adapter/` 下无 `jcodeindexer` 包、解析注册中心也未接线），不应视为可用适配器。此前文档误列其为高优先级适配器，已更正。

## ⚠️ CallerFQN 行为（影响面分析的关键）

- **建边条件**：`internal/analyzer/analyzer.go` 仅当 `call.CallerFQN != ""` 才建立调用边。
- **Go（默认 tree-sitter 正则路径，`adapter.go`，即 `-tags` 默认构建）**：`da20964` 修复回填了调用方 `CallerFQN`（Go 专属方法作用域跟踪，`detectCalls` 的 `caller` 参数为当前方法 FQN）。但回填的 FQN 曾为**裸名**（如 `Watcher.ReloadNow`），与查询用的包限定全名（如 `config.Watcher.ReloadNow`）**命名空间错位**，impact 仍恒空。`T1`（2026-09-02）在 adapter 中以 `package` 声明为前缀产出包限定 FQN（`config.Watcher.ReloadNow`；自调用 `w.ReloadNow` 经 receiver 变量识别限定为 `config.Watcher.ReloadNow`），并在 analyzer 加双向归一化，至此 **`impact` / `tests` / `get_call_graph` 对 Go 默认真实可用**。
- **非 Go 语言（默认正则路径）**：`detectCalls` 对其它语言传 `caller`（来自当前方法作用域，无则空），caller/callee 默认走裸名启发式；**P19（2026-09-03）补齐显式包声明的三类语言包限定**——Java `package`、Kotlin `package`、C# `namespace` 在解析时捕获并作为 `caller` FQN 前缀（`com.example.OrderService.createOrder`），对齐 Go 的包限定命名空间；callee 因依赖类型消歧保持裸名。Python（以文件路径推导模块）、TypeScript（`import/export` 非包声明）、Rust（嵌套 `mod` 树）、C++（命名空间可多段嵌套）按「语种类别逐步收敛」留待后续。analyzer 双向归一化保证查询鲁棒。
- **LSP / SCIP / CodeGraph 适配器**：由对应适配器回填 `CallerFQN`，跨语言可用。
- 小结：默认栈下 **Go 的影响面分析已可用（T1 命名空间对齐后）**；非 Go 走裸名启发式，双向归一化保证查询鲁棒。（历史上默认路径全空属缺陷，已修复，非设计行为；`adapter.go` 与 `adapter_ast.go` 双路径均已对齐 `CallerFQN` 回填，T1 进一步补齐包限定。）

## 变量 / 常量 IR（2026-09-03 新增，仅 Go 默认正则路径）

- 默认正则路径（`adapter.go`）在产出 `ClassIR`/`MethodIR`/`CallIR` 之外，新增两类 IR，随 `UpsertIR`/`BulkUpsert` 自动落库（仅 PG 后端 `field`/`constant` 表，见[存储后端.md](存储后端.md)）：
  - **成员变量** → `FieldIR{ClassFQN}`：`type X struct { ... }` 体内的字段行（含 tag 行，tag 剔除后取类型）；仅非方法体内提取。
  - **包级常量** → `ConstantIR{FilePath}`：`const X [Type] = v` 单行与 `const ( ... )` 块内行；方法内 `const` 忽略（局部常量不入库）。
- **已知坑（T 修复）**：`const ( ... )` 块的闭合行 `)` 必须在 `constBlock` 激活时进入常量分支，否则 `constBlock` 无法复位，会吞掉其后所有行（含 struct 字段行，导致 `Fields` 恒空）。

## 新增一个适配器

1. 在 `internal/parser/adapter/<name>/` 实现 `Adapter` 接口，产出 `parser.MethodIR` / `CallIR`（**务必回填 `CallerFQN`**）。
2. 在 `cmd/codeschema` 的分发处接线（受 build tag 约束时加对应 tag）。
3. 在配置 `parser.adapters` 文档与示例里登记（`parser.adapters` 为声明性清单，运行时注册由 `parser.lsp.enabled` / `parser.scip.index_dir` / `parser.codegraph.db` 驱动，见上文）。
4. 补单测（真实语言工程验证），同步更新文档与 `make counts`（若新增包）。
