# 解析适配器

> 写给：要新增语言支持或理解解析行为的开发者

> 最后更新：2026-09-02
## 适配器总览

解析层 `internal/parser/adapter` 按语言/精度选择适配器，产出统一 IR（类/方法/调用关系）：

| 适配器 | 精度 | 启用方式 | 备注 |
|---|---|---|---|
| `treesitter` | 中（默认） | `parser.adapters: [treesitter]` | 正则启发式，30 语言，零 CGO；`-tags treesitter` 切真语法树 |
| `codegraph` | 高 | `parser.codegraph.db` 配置 | 接 CodeGraph 索引库 |
| `scip` | 高 | `parser.scip.index_dir` | SCIP index |
| `lsp` | 高 | `parser.lsp.enabled: true` | 按语言分发 gopls/jdtls/clangd；缺失自动回退 tree-sitter |

> **`jcodeindexer` 为配置预留、尚未实现**：`parser.jcodeindexer` 仅是 `config.yaml` 的配置字段（见 `internal/config/parse.go`），目前**无对应适配器实现**（`internal/parser/adapter/` 下无 `jcodeindexer` 包、解析注册中心也未接线），不应视为可用适配器。此前文档误列其为高优先级适配器，已更正。

## ⚠️ CallerFQN 行为（影响面分析的关键）

- **建边条件**：`internal/analyzer/analyzer.go` 仅当 `call.CallerFQN != ""` 才建立调用边。
- **Go（默认 tree-sitter 正则路径，`adapter.go`，即 `-tags` 默认构建）**：自 `da20964` 修复后，已通过 Go 专属结构跟踪（`currentMethod` 方法作用域）回填调用方 `CallerFQN`——`detectCalls` 的 `caller` 参数即当前方法 FQN。因此 `impact` / `tests` / `get_call_graph` 对 **Go** 代码**默认即可用**。
- **非 Go 语言（默认正则路径）**：`detectCalls` 对其它语言传 `caller=""`（与旧行为一致），`CallerFQN` 为空 → 影响面分析对该语言默认返回空。
- **LSP / SCIP / CodeGraph 适配器**：由对应适配器回填 `CallerFQN`，跨语言可用。
- 小结：默认栈下 **Go 的影响面分析已可用**；其它语言需启用 LSP / SCIP / CodeGraph 才回填 `CallerFQN`。（历史上默认路径全空属缺陷，已修复，非设计行为；`adapter.go` 与 `adapter_ast.go` 双路径均已对齐 `CallerFQN` 回填。）

## 新增一个适配器

1. 在 `internal/parser/adapter/<name>/` 实现 `Adapter` 接口，产出 `parser.MethodIR` / `CallIR`（**务必回填 `CallerFQN`**）。
2. 在 `cmd/codeschema` 的分发处接线（受 build tag 约束时加对应 tag）。
3. 在配置 `parser.adapters` 文档与示例里登记。
4. 补单测（真实语言工程验证），同步更新文档与 `make counts`（若新增包）。
